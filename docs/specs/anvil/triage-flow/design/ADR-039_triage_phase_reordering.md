# ADR-039 トリアージ Phase 順序の転換: 判定前の一括調査から早期判定併用への変更

## 1. コンテキスト

`anvil:triage-issue` の既存 Phase 構成は、Phase 2〜5（仕様書検索・ルール検索・類似 PR 調査・既存コード調査）を判定（Phase 6〜8）より前に一括実行する。この順序は、明白なケース（例: バグ修正であることが Issue 本文から一意に判定できる場合）でも、判定確定前に重い調査をすべて終える必要があり非効率である。

一方で、判定の一部（`additive_development_spec.md` §1 の適用条件チェック、要件確定性の判定、リスクゲート条件1・2）は Issue 本文の記述のみで判定可能であり、Phase 2〜5 の調査結果を必要としない。

## 2. 決定

> **本決定は未承認である。** 以下は提案として記録したものであり、承認を経ていない。

判定を「Issue 本文のみで直行可能な判定」と「Phase 4〜5 の調査結果を要する判定」に分離し、直行可能な判定を Phase 2〜5 の前に移動する。

**§1 適用条件チェック（新設 Phase 6.5）は一方向の早期終了ゲートとしてのみ使う**: `additive_development_spec.md` §1 の適用条件（旧仕様の存在・新規要件群・分離管理価値）が真の場合のみ SDD ルート（feature 必要）に早期確定する。**§1 が偽の場合は何も確定させず、通常の判定（Phase 6・Phase 7）を継続する**。§1 の非適用は「feature 分離管理が不要」を意味するに留まり、「SDD 自体が不要（軽量実装でよい）」を意味しない（feature 分離が不要でも、設計判断や高リスクを伴うバグ修正・リファクタリングは Phase 7 のリスクゲートを経て SDD ルートに進むべきケースがあるため）。

Phase 6 判定2（設計判断の残余）・Phase 7 条件3（波及範囲）が Phase 4〜5 の調査結果を要するという既存の依存関係は変更しない。Phase 4〜5 はこれらの判定より前に実行する（判定確定後に後ろ倒しにしない）。

Phase 2・Phase 3（仕様書検索・ルール検索）は判定への直接の依存が弱いため、ルート確定後に impl-issue / forge の SDD エントリポイントへの申し送り専用として実行する位置づけに変更する。

## 3. 検討した代替案

| 代替案                                       | 棄却理由                                                                                                                                                          |
| -------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| §1 非適用時にも軽量実装ルートへ早期確定する  | §1 が判定する「feature 分離管理の要否」と「SDD の要否」は別軸であり、高リスクなバグ修正・リファクタリングを誤って軽量実装に確定させる欠陥がある（レビューで検出） |
| Phase 2〜5 すべてを判定確定後に後ろ倒しする  | Phase 6 判定2・Phase 7 条件3 が Phase 4〜5 の調査結果を判定の直接根拠として要求するため、判定前に実行する必要がある                                               |
| 既存の Phase 順序（一括調査→判定）を維持する | 直行可能な判定がある場合でも重い調査を待つ非効率が解消されない                                                                                                    |

## 4. 影響

判定を「直行可能な早期チェック」と「調査を要する最終判定」に分離することで、明白なケースでの判定コストを下げつつ、§1 の適用範囲を超えた誤判定（軽量実装への不当な早期確定）を防ぐ。Phase 6 判定2・Phase 7 条件3 が要求する調査結果の依存関係は変更しないため、既存の調査手順書（triage-issue の Phase 別 references）への影響は実行順序のみに限定される。
