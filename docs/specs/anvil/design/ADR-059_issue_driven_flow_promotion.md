# ADR-059 issue-driven-flow を anvil 恒久仕様へ位置づけ直し、差分開発の齟齬解消先とする

## メタデータ

| 項目     | 値                                    |
| -------- | ------------------------------------- |
| ADR ID   | ADR-059                               |
| Status   | accepted                              |
| 決定日   | 2026-08-01                            |
| 関連設計 | REQ-005 / DES-025 / REQ-007 / DES-038 |

## 1. コンテキスト

anvil の開発フロー仕様は 2 つの一時 feature 文書群として存在していた。

- **issue-driven-flow**（REQ-005 / DES-025）: GitHub Issue を起点にした SDD パイプライン連携。`temporary-feature-*` frontmatter を持つ
- **triage-flow**（REQ-007 / DES-038）: issue-driven-flow に対する差分開発（トリアージ工程の導入）

いずれも実装は完了し配布済みだが、merge（齟齬解消）が実施されないまま一時文書が残存していた。齟齬解消を行おうにも、**anvil には「旧仕様」にあたる恒久文書が存在しない**。issue-driven-flow は anvil に開発フローという要件群を初めて導入した文書であり、frontmatter が前提とする「据え置かれて古くなった旧仕様」が最初から無かった。

## 2. 決定

issue-driven-flow（REQ-005 / DES-025）の一時位置づけを撤回し、`docs/specs/anvil/{requirements,design}/` へ移動して anvil の恒久仕様とする。frontmatter・一時注記は除去する。ID・本文は変更しない。

以後の anvil 差分開発（triage-flow を含む）は、この恒久仕様を齟齬解消（merge）の相手として扱う。スコープが同じ内容は恒久仕様側へ移し、スコープが異なる内容は分離したまま維持する（`additive_development_spec.md` §4.2 の判断基準に従う）。

決め手は、issue-driven-flow が実質的に **anvil 本体の仕様そのもの**であることである。frontmatter の意味論（旧仕様が正本より古い状態にあり、実装完了後に齟齬を解消する必要がある）は、齟齬を解消すべき旧仕様が存在しないこの文書には最初から成立していなかった。位置づけを事実に合わせることが、この決定の実体である。

## 3. 検討した代替案

| 代替案                                             | 棄却理由                                                                                                          |
| -------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| anvil 恒久仕様を新規 ID で書き起こし、旧文書を削除 | 内容は REQ-005 / DES-025 と同一になる。転記だけの新文書は ID の付け替えに過ぎず、参照の張り替えコストだけが生じる |
| 実装済みであることを根拠に文書群を単純削除         | anvil 開発フローの仕様の SoT が失われ、SDD の前提（文書駆動）が崩れる                                             |
| 一時文書のまま残置                                 | 成立し得ない意味論（存在しない旧仕様との齟齬解消）を宣言する frontmatter が恒久的に残る                           |

## 4. 影響

**得られるもの**

- anvil に恒久仕様の置き場（`docs/specs/anvil/{requirements,design}/`）が確立し、以後の anvil 差分開発は通常どおりここを齟齬解消の相手にできる
- issue-driven-flow の frontmatter 宣言と実態の乖離が解消される

**失うもの・新たに生じる制約**

- REQ-005 / DES-025 は恒久文書になるため、以後の変更で feature 判定条件を満たすものは差分 feature（一時文書）として切り出す通常ルールの対象になる
- frontmatter の「この文書が正（旧仕様より優先）」という優先宣言が失われる。実装完了済みのため実害はない
- triage-flow（REQ-007 / DES-038）の齟齬解消は本決定の後続作業であり、スコープ判断（恒久仕様へ移すか、分離維持して frontmatter を外すか）を別途行う
