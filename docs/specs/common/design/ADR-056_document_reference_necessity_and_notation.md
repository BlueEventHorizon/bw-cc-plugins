# ADR-056 文書間参照の必要性判定と記法（配布物の適用除外）

## 1. コンテキスト

`CLAUDE.md`「文書間参照にパスを焼き込まない」は主語を「文書」とだけ書き、適用範囲を限定していなかった。その結果、以下の矛盾と誤運用が生じた。

### 1.1 SoT の正面衝突

ADR-052 §2.1 と forge の `document_style_guide.md` §5.1 は、`plugins/forge/docs/` 内の相互参照に **相対マークダウンリンクを義務づけている**。理由は AI の参照負荷であり、`${CLAUDE_PLUGIN_ROOT}` が直接 Read 経路で解決されず実体パス推測のコストが毎回発生することを実測に基づいて記録している。一方 `CLAUDE.md` は無限定にパス直書きを禁じていたため、同一リポジトリ内で「配布物にリンクを書け」と「文書にパスを書くな」が同時に有効な状態になっていた。

### 1.2 誤運用の実例

配布物・プロジェクト文書の双方を横断する改訂作業において、AI がこの無限定な禁止を全体規範として解釈し、`docs/specs/` 相互参照を ID ベースへ寄せる方向で判断した。しかし ID ベース参照は、参照先へ到達するために全文検索または `query-docs` の起動を要求する（実測で 1 回あたり数万トークン規模）。これは「AI が間違いなく、負荷なく文書を参照できる」という文書設計の目的に反する。

### 1.3 参照の 2 用途が混同されていた

- **発見**: 「このタスクで何を読むべきか」が未確定な状態から関連文書を見つける
- **既知文書への参照**: 参照先が確定しており、その 1 文書を直接読む

doc-advisor（`query-docs`）が解決するのは前者である。後者にまで「パスを書かず ID で表現する」を適用すると、確定している宛先をわざわざ検索し直させることになる。

## 2. 決定

### 2.1 プロジェクト文書（`docs/` 配下）— 必要性判定を第 1 原則とする

参照リンクは**書かないことを既定**とし、書いてよいのはそれを書かなければ本文の主張・規定が理解・検証できない場合に限る。条文は [spec_format.md](../../../../plugins/forge/docs/spec_format.md)「文書参照の記法」と [document_writing_rules.md](../../../rules/document_writing_rules.md) が定める。

**採用理由**: 必要のない参照は保守対象としてのみ残り、参照先の改訂・削除でサイレントに腐る。実際に、旧レビューパイプラインの設計書を削除した際、`ADR-033` / `DES-014` / `DES-029` / `REQ-005` を指す参照が複数文書に生き残り、外部レビューで指摘されるまで検出されなかった。これらはいずれも「発見」ではなく惰性で書かれた道しるべであり、本文を自己完結させれば不要だった。

### 2.2 プロジェクト文書 — 書く場合はマークダウンリンク方式

必要と判断した参照は `[表示名](相対パス)` 形式で書く。地の文でのパス直書き、リンクなしのファイル名言及、ID のみで「ここを見ろ」を意味させる参照は用いない。条文は §2.1 と同じ 2 文書が定める。

**採用理由**: 参照先が確定している以上、AI は検索を経ずそのまま Read できるべきである（1.3 の後者）。リンク切れは機械検出できるため、参照先が消えた事実が沈黙せず表面化する。

### 2.3 メタデータの `関連要件` / `関連設計` は ID のみ（暫定）

これらはナビゲーションではなく**依存関係の記録**である。ID のみを記載し、リンクにしない。

> **本項は暫定規定である。** 「ナビゲーションではない」という区分けは支持しにくい——当該行を機械は読んでおらず（`plugins/` 配下に `関連要件` / `関連設計` をパースする script は存在しない）、読者が人間と AI だけである以上、AI が検索を経ずに到達できる形式であるべきという §2.2 の理由がそのまま当てはまる。ID のままにしている実務的理由は、Markdown 表のセルが自由記述を含むため参照切れ検証が誤検出を量産することであり、メタデータの構造を決めるまでの暫定とする。

### 2.4 配布物（`plugins/` 配下）は 2.1 / 2.2 の適用対象外

配布物は決定論的に閉じた木として配布されるため、開発者責任で内部リンクを書く。記法は forge の `document_style_guide.md` §5.1（ADR-052 §2.1 / §2.2）に従う。

**採用理由**: 配布物内のパスは配布単位の中で完結しており、利用者環境でも同一の相対関係が保たれる。プロジェクト文書のパスが改訂で動くのとは前提が異なる。

> 本項は「配布物の内部でリンクを書いてよい」という許可であり、ADR-055（配布物からプロジェクト開発文書を参照しない）を緩めるものではない。配布物からリポジトリルートの `docs/` を参照することは、パス・spec ID のいずれの形式でも引き続き禁止である。

## 3. 検討した代替案

| 代替案                                                             | 棄却理由                                                                                                            |
| ------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------- |
| `docs/specs/` 相互参照も ID ベースに統一する（改訂前の規定を維持） | 参照先が確定している宛先に対して検索を強制する。ID 衝突（異なる spec ディレクトリの同番号）が実在し、裸の ID は曖昧 |
| 全文書（配布物含む）でパス参照を一律禁止する（改訂前の CLAUDE.md） | ADR-052 §2.1 と正面衝突する。配布物と プロジェクト文書でパスの安定性の前提が異なる事実を無視している                |
| 必要性判定を設けず、参照は常にマークダウンリンクで書いてよいとする | 不要な参照が増え、参照先の改訂・削除のたびに保守対象が膨らむ。`query-docs` が発見を担う設計の意義が薄れる           |
| 参照切れの検出をリンク方式ではなく契約テストのみで担保する         | 検出は可能だが、AI が参照先へ到達する負荷（1.2）は解決しない。テストは併用する（本 ADR はテストを排除しない）       |

## 4. 影響

`CLAUDE.md` の該当箇条書きを 2 項に分割し、適用範囲（プロジェクト文書）と配布物の適用除外を明示した。`docs/rules/document_writing_rules.md` §4.5 を、必要性判定（第 1 原則）とマークダウンリンク記法（第 2 原則）＋適用範囲の構成へ改訂した。

得られるもの: 配布物とプロジェクト文書で相反する規定が同時に有効な状態が解消される。必要な参照は AI が検索なしで到達でき、不要な参照は最初から書かれない。

失うもの・新たに生じる制約: 執筆者が参照ごとに必要性を判断する必要が生じる。マークダウンリンクの相対パスは参照元・参照先の移動で壊れるため、リンク切れ検査を別途持つ必要がある。

### 4.1 配布物 `spec_format.md` への適用

forge の配布物 `spec_format.md` は、利用者プロジェクトの spec 文書について「相対パス・絶対パスでの specs/ 文書参照」を禁止し ID ベースを規定していた。本 ADR の 2.1 〜 2.3 と方針が異なるため、同じ構成（必要性判定 → マークダウンリンク → メタデータは ID のみ）へ統一した。

これは forge を導入した全プロジェクトの spec 文書執筆規約が変わることを意味する。別 spec ディレクトリの ID を修飾する `{spec-dir}:{ファイル名}` 記法は、リンクにしないメタデータの `関連要件` / `関連設計` 専用として存続させる（本文中の「ここを見ろ」参照としては用いない）。
