# ADR-071 外部依存のない agent-review を既定第一候補とする

## 1. コンテキスト

ADR-067 は、明示指定がない場合に候補を順に可用性検査して最初に使えるバックエンドを選ぶことと、可用性検査を共通契約へ加えることを決定した。同時に履歴復元も共通契約へ加え、既定候補の具体的な順序は後続設計に委ねた。

既存の `msg-review` は、msg-sys の DB、cmux、常駐 Codex セッションを必要とする。これらは人間が進行を見ながら常駐セッションと継続対話するための有用な性質だが、通常のレビューを開始するための既定前提としては重い。外部依存がない環境では可用性検査で不成立となり、後続候補がなければレビュー自体を実行できない。

一方、Claude Code のカスタム Agent はプラグイン内に同梱できる。read-only の `reviewer` を各ラウンドで新規起動すれば、常駐セッション、メッセージ DB、履歴復元、終了時に解放する資源を持たずに共通のラウンド結果を返せる。

この構成を共通契約へ接続すると、次の 2 点が ADR-067 の決定と衝突する。

1. 履歴復元は、非永続バックエンドには提供できず、レビューの成立にも必要ない
2. 共通依頼本文の `[msg-review]` ヘッダは msg-sys 上のスレッド識別子であり、他バックエンドには意味がない

## 2. 決定

### 2.1 既定の候補順

明示指定がない場合の候補順を次のとおりとする。

1. `agent-review`
2. `msg-review`

外部依存を持たず、プラグイン単体で利用できる `agent-review` を第一候補とする。`msg-review` は、利用者が明示指定した場合、または第一候補を利用できない場合に選ばれる。

選択は依頼送信前に完了し、ラウンド実行後の `failure` を契機に別バックエンドへ切り替えない。`--backend` またはプロジェクト設定による明示指定が利用不可なら、従来どおり fail closed とする。

### 2.2 履歴復元を任意拡張とする

履歴復元を共通バックエンド契約から外す。バックエンドは、ラウンド実行、可用性検査、終了通知の 3 要求を共通契約として満たす。

履歴復元は、永続的な往復記録を持つバックエンドが提供できる任意拡張とする。`msg-review` はこの拡張を引き続き提供する。履歴を持たないバックエンドのレビューが中断した場合、本体は同一レビューの再開を試みず、新しい `review_id` の新規レビューとして再実行する。

### 2.3 ワイヤヘッダをバックエンド内部へ移す

共通依頼本文から `{{PROTOCOL_HEADER}}` と `[msg-review]` ヘッダを除く。共通本文はレビュー対象、観点、重点観点、到達目標、返信形式契約だけを表す。

`msg-review` は送信直前に次のヘッダを本文先頭へ付加する。

```text
[msg-review] <種別> review_id=<review_id> round=<n>
```

受信、スレッド識別、履歴抽出に必要なヘッダの生成と検証は `msg-review` 内部の責務とする。他のバックエンドはこのヘッダを受け取らず、付加しない。

### 2.4 msg-review のラウンドを同期境界とする

`msg-review` のラウンド実行は、送信、相手ターンの起床、応答待機、応答解釈を 1 回の同期境界として完結させる。Stop フックで差し戻されたメッセージはラウンド実行や自動再開の起動契機にしない。

待機予算内に応答が得られない場合は、そのラウンドの確定した `failure` とする。タイムアウト後の遅延返信を自動処理せず、非同期処理へ移ったものとして本体を継続させない。

永続記録の確認は、利用者または本体が `review_id` を明示した履歴復元要求に限る。履歴復元はラウンドの自動継続やタイムアウトからの自動復帰として扱わない。

## 3. 検討した代替案

| 代替案                                       | 棄却理由                                                                                     |
| -------------------------------------------- | -------------------------------------------------------------------------------------------- |
| `msg-review` を第一候補のまま維持する        | 外部ツールと常駐セッションを既定前提にし、プラグイン単体でレビューを開始できない             |
| 履歴復元を全バックエンドへ義務づける         | 非永続バックエンドに DB または記録層を追加させ、ラウンド実行に不要な状態管理を強制する       |
| `agent-review` に擬似的な空履歴を返させる    | 往復が無かった状態と復元不能を区別できず、存在しない継続性を本体へ示す                       |
| 共通本文に `[msg-review]` ヘッダを残す       | msg-sys 固有のワイヤプロトコルが全バックエンドの依頼契約へ漏れ、抽象境界が実行主体に依存する |
| 中断した `agent-review` を同じ ID で再開する | ラウンド間の Agent も履歴も保持しないため、同一レビューとして復元できる状態が存在しない      |

## 4. 影響

**得られるもの**

- 外部ツール、DB、常駐プロセスの準備なしで既定レビューを実行できる
- 共通契約が、状態を持つバックエンドと持たないバックエンドの双方に適用できる
- msg-sys 固有のヘッダ生成・検証・履歴抽出が `msg-review` 内に閉じる
- `agent-review` はラウンドごとに新しい read-only Agent を使い、前ラウンドの暗黙コンテキストへ依存しない

**失うもの・新たに生じる制約**

- 既定経路では、人間が常駐レビュアーの進行を画面で確認し途中介入する性質を持たない
- `agent-review` の中断後は同一レビューを復元できず、依頼本文を再構築して新規レビューとして実行する
- 本体の再開モードは、選択したバックエンドが履歴復元拡張を提供する場合に限って利用できる
- `msg-review` は共通本文を受け取った後、送信前にワイヤヘッダを確実に付加する必要がある
