# ADR-069 `${CLAUDE_PLUGIN_ROOT}` 実体 symlink 自己修復機構の廃止

## 1. コンテキスト

ADR-052 §2.4 は、marketplace インストール環境で `${CLAUDE_PLUGIN_ROOT}` の実体が非決定的なキャッシュパスになる問題（ADR-052 §1.3）への対処として、SessionStart hook による symlink 自己修復機構を導入した。セッション開始のたびに利用プロジェクトの `.claude/` 配下へプラグイン実体 `docs/` への symlink を作成し、利用プロジェクトの `.gitignore` へ非追跡エントリを自動追記する。

運用の結果、この機構には利便性を上回る問題があることが判明した。

- **利用プロジェクトへの越権的な副作用**: forge を導入した全プロジェクトで、セッションを開くだけで作業ツリー（symlink 生成）と `.gitignore`（自動追記）が書き換わる。プラグインが利用者の管理物を無断で改変する構造であり、利用者から見ると git が汚れる
- **消費者が存在しない**: 全 hook・全 SKILL・全 script・Codex 連携を対象に依存を全数調査した結果、この symlink を読む消費者はゼロだった。想定していた 3 つの経路はいずれも symlink なしで成立している
  - hooks の command 文字列: Claude Code が spawn 前に `${CLAUDE_PLUGIN_ROOT}` を実パスへ置換する（ADR-052 §1 の実測どおり）
  - SKILL 起動時のコンテキスト注入: 同様に実パスへ解決される（同実測）
  - 外部レビュアー（Codex）への文書パス伝達: レビュー依頼構築 script が自身の設置場所（`__file__`）から実体を逆算し、解決済み絶対パスを依頼本文に埋め込む
- 残る「スキル起動を経由しない直接 Read」の場面は、プロセス起動引数の逆引き手順（CLAUDE.md「外部プラグインの実体確認」）で従来どおり対応できる

## 2. 決定

symlink 自己修復機構を廃止する。SessionStart hook の登録・自己修復 script・その単体テスト・本リポジトリ `.gitignore` の対応エントリを削除する。

`${CLAUDE_PLUGIN_ROOT}` 実体へのアクセスは、経路ごとに既存の解決手段へ一本化する。

| 経路                            | 解決手段                                      |
| ------------------------------- | --------------------------------------------- |
| hooks の command 文字列         | Claude Code のネイティブ置換（従来どおり）    |
| SKILL 起動時の本文注入          | Claude Code のネイティブ置換（従来どおり）    |
| script からの実体参照           | script 自身の設置場所（`__file__`）からの逆算 |
| スキル起動を経由しない直接 Read | プロセス起動引数の逆引き手順（CLAUDE.md）     |

ADR-052 の他の決定（§2.1 相対パス統一・§2.2 外部からのフルパス表記・§2.3 スタイルガイド改訂）は本 ADR の対象外であり、引き続き有効である。

## 3. 検討した代替案

| 代替案                                                                        | 棄却理由                                                                                                                   |
| ----------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| 機構を維持し `.gitignore` 自動追記のみやめる                                  | symlink が untracked として利用プロジェクトの `git status` に常時出るため、git が汚れる問題はむしろ悪化する                |
| symlink をやめ、実体パスのポインタをユーザーレベル（`~/.claude/` 配下）へ置く | 利用プロジェクトは汚さないが、プロジェクトと実体の対応管理という新しい複雑さが入る。消費者ゼロの機構の置き換えとしては過剰 |
| 現状維持                                                                      | 消費者が存在しないまま、利用プロジェクトへの副作用と機構の保守コスト（script・テスト）だけが残り続ける                     |

## 4. 影響

得られるもの: forge 導入プロジェクトへの無断の作業ツリー改変・`.gitignore` 改変がなくなる。消費者のない機構の保守（script・単体テストの維持）が不要になる。

失うもの・新たに生じる制約: スキル起動を経由しない直接 Read でダウンストリーム実体へアクセスする際の固定パスがなくなり、逆引き手順に戻る（実測上この経路の利用実績はない）。**既に forge を導入済みのプロジェクトに生成された symlink と `.gitignore` 追記行は、hook を削除しても自動では消えない**。実害はないが、リリースノートで手動削除を案内する。
