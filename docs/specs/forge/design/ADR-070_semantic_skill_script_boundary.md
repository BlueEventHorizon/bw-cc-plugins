# ADR-070 SKILL と script の境界を構文ではなく意味的選択で定める

## 1. コンテキスト

REQ-003 と DES-024 は、AI の判断負担を減らす手段として「位置引数のみ」「flag 付き呼び出しを
書かない」「意味論が異なる operation は別 script に分ける」を全 SKILL に適用していた。

しかし、SKILL は進行管理・判断分岐・ユーザー対話を担うオーケストレーターでもある。実際に
同期ジョブの投入と状態取得は、利用者へ進捗を届けるため SKILL が順に駆動する必要がある。
この `start` / `status` は同一場面で自由に選ぶ方針ではなく、同一ジョブの順序付き位相である。
別 script に分けても、AI の選択対象が flag からファイル名へ移るだけで判断負担は減らない。

また、名前付き引数は複数の実行時データの意味を明示し、位置引数より取り違えを防ぐ場合がある。
構文形式やファイル数を設計目的の代理指標にすると、本来減らすべき意味的な自由度を判定できない。

## 2. 決定

SKILL と script の境界は、AI に残る **未決定の意味的選択** を基準に定める。

- SKILL はユーザー意図の解釈、進行管理、現在状態に基づく分岐、ユーザー対話を担う
- script は固定値の適用、機械的な導出・変換・検証、決定論的処理を担う
- SKILL によって一意に決まる値は、SKILL ローカルの操作入口へ束縛する
- 前段の結果やユーザー入力として自然に得られる実行時データは、位置引数または名前付き引数で渡してよい
- 同一場面で競合する意味的操作は別入口へ分ける
- 同一資源の順序付き位相は、場面ごとに呼び出しが確定していれば同じ入口の明示モードとしてよい
- ラッパーは低レベル CLI の全引数を無条件に公開せず、当該 SKILL が必要とする契約だけを公開する

位置引数、名前付き引数、subcommand、script 分割は上記境界を実現する手段として個別に選ぶ。
いずれかを一律に必須または禁止しない。

## 3. 検討した代替案

| 代替案                                        | 棄却理由                                                               |
| --------------------------------------------- | ---------------------------------------------------------------------- |
| flag 付き呼び出しをすべて別 script へ分割する | 選択対象を flag からファイル名へ移すだけで、順序付き位相まで分断する   |
| 位置引数だけを許可する                        | 複数値の意味が不明瞭になり、名前付き引数より取り違えやすい場合がある   |
| 共有低レベル CLI を SKILL.md から直接呼ぶ     | SKILL 固有値と共有実装の配置を AI が組み立てる必要があり、局所性を失う |
| 低レベル CLI の全引数をラッパーから透過する   | 低レベルへの機能追加が無関係な SKILL の公開契約へ自動的に漏れる        |
| operation ごとに常に別ラッパーを作る          | 同一資源の凝集性を失い、ファイルとテストだけが増える                   |

## 4. 影響

**得られるもの**

- AI の判断負担を、構文の数ではなく意味的な選択肢の有無で評価できる
- SKILL 固有値を束縛する意図的なローカルラッパーを維持できる
- 同期ジョブの投入・状態取得のような凝集した位相を同じ入口で表現できる
- ラッパーが公開する契約を低レベル CLI の将来追加から隔離できる

**失うもの・新たに生じる制約**

- grep による「flag があるか」だけでは設計適合を判定できない
- ラッパーごとに、固定値・実行時データ・意味的選択の分類が必要になる
- 既存の無制限な引数透過は、公開契約を明示する実装とテストへ改める必要がある
