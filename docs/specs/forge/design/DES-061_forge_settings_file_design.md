# DES-061 forge プロジェクト設定ファイル設計

## 1. 概要

forge の挙動をプロジェクト単位で調整するための汎用設定ファイル `.claude/.forge.yaml` を定義する。
1 つのファイルに複数の機能領域の設定を併記でき、各領域のスキーマはその機能を所有する設計文書が定義する。
本設計が定めるのは **入れ物の規約**（配置・構造・読み取り・エラーの扱い）だけであり、個々の設定値の意味は定めない。

最初の利用側は doc-db バックエンド選択（REQ-014 / DES-057）の優先 backend 指定である。

### 既存設定ファイルとの関係

forge には目的特化の設定ファイルが既にある。本設計はそれらを置き換えない。

| ファイル                      | 役割                                    | 本設計との関係           |
| ----------------------------- | --------------------------------------- | ------------------------ |
| `.doc_structure.yaml`         | 文書パスの解決（rules / specs の所在）  | 独立して維持。移行しない |
| `.version-config.yaml`        | バージョン一括更新の対象定義            | 独立して維持。移行しない |
| `.claude/.forge.yaml`（新規） | 上記に当てはまらない forge の挙動の調整 | 本設計が定義             |

既存 2 ファイルは「プロジェクトの構造の宣言」であり、`.claude/.forge.yaml` は「forge の挙動の調整」である。
新しい設定項目は、構造の宣言でない限り `.claude/.forge.yaml` のセクションとして追加する（設定ファイルを増やさない）。
既存 2 ファイルの配置（プロジェクトルート直下）は互換のため変更しない。

## 2. 設計方針

### 2.1 ファイルの規約

- 配置は `.claude/.forge.yaml` とする。plugin の挙動調整はプロジェクトの `.claude/` 配下に置く
  （doc-advisor が `.claude/.doc-advisor/` を使うのと同じ流儀）。git 管理対象であり、プロジェクト固有の
  設定としてチームに共有される。一時物置き場（`.claude/.temp/` 等）には置かない。
- ファイルは**任意**である。存在しない場合、すべての機能は既定の挙動で動作する。
- トップレベルのキーは**機能領域ごとのセクション**とする。セクション名と配下のスキーマは、
  その機能を所有する設計文書が定義・所有する。本設計はセクションを列挙しない
  （列挙すると新セクション追加のたびに本設計が陳腐化する）。
- 未知のセクションは**無視する**。あるバージョンの forge が知らないセクションが書かれていても、
  既知のセクションの読み取りは成功する（前方互換）。ただしファイルは全体を §2.3 のサブセットとして
  解析するため、**前方互換が成立するのは未知セクションもサブセットの範囲内で記述されている場合に限る**。
  サブセット外の構文はどのセクションにあってもファイル全体が解析不能になる。したがってセクションを
  新設する設計は、スキーマをサブセットの範囲内で定義しなければならない。

```yaml
# .claude/.forge.yaml — 記述例（セクション名は例示）
doc_backend:
  prefer: doc-advisor

foo_feature:
  bar: value
  items:
    - one
    - two
```

### 2.2 スキーマの所有と衝突の回避

- 各セクションのスキーマ（キー・値域・既定値・不正値の扱い）は利用側の設計文書が所有する。
  セクションを新設する設計は、セクション名と配下スキーマを自文書に定義する。
- セクション名は機能領域を表す snake_case とし、既存セクションと重複しないことを新設時に確認する。
- 1 セクションを複数の機能が読むことは許容するが、**書式の定義者は 1 文書**に限る。
- セクションを新設する設計は、**設定が無い場合の既定の挙動を必ず定義する**。ファイルは任意（§2.1）で
  あるため、既定が未定義のセクションは「設定が無い環境で挙動が決まらない」機能を生む。

### 2.3 読み取り境界

- 読み取りは共有低レベルモジュール `plugins/forge/scripts/forge_settings.py`（新規）に一元化する。
  各 script が独自に `.forge.yaml` をパースしない。
- パーサは Python 標準ライブラリのみで実装する。`.doc_structure.yaml` と同系の行ベースパーサとし、
  対応する構文は**制約付き YAML サブセット**（ネストした mapping、スカラー、文字列リスト、コメント）に限る。
  アンカー・複数行文字列・flow style は対象外であり、出現した場合は解析不能として扱う。
- 公開 I/F は次の 2 つに限る。

| 関数                          | 返り値                                                               |
| ----------------------------- | -------------------------------------------------------------------- |
| `load(project_root)`          | ファイル全体の dict（不在なら空 dict）。解析不能なら `SettingsError` |
| `section(project_root, name)` | 当該セクションの dict（不在・ファイル不在なら空 dict）。同上         |

### 2.4 エラーの扱い

- **ファイル不在は正常**（設定なし＝既定動作）。エラーにも警告にもしない。
- **解析不能は明示エラー**とする。読めない設定を黙って無視して既定動作に落ちると、利用者が意図した
  調整と異なる挙動で静かに動き続けるためである（フォールバックを反射的に書かない）。
  エラーには「`.claude/.forge.yaml` の何行目付近が解析できないか」を含め、設定本文の全文は出力しない。
- **値の検証は利用側の責務**とする。`forge_settings.py` は構文だけを扱い、値域（許容値・型）の
  判定と不正値時の挙動は各セクションの所有設計が定める。

### 2.5 ファイルの作成経路

`.claude/.forge.yaml` は手書きで作成・編集する。ファイルは任意（§2.1）であるため、作成を支援する
仕組みは利用の前提条件ではなく、本設計は特定の作成手段を前提にしない。

対話的に雛形を生成する setup SKILL の提供は**本設計の対象外**である。それは新たな公開名・対話フロー・
配布物を伴う独立した機能であり、必要になった時点で要件定義から起こす（その要件定義では、各セクションの
スキーマ定義が所有設計へ分散している構造（§2.2）に対して、生成側がセクション一覧と既定値をどこから
得るかの契約を解決する必要がある）。

## 3. テスト設計

`forge_settings.py` は `plugins/` 配下の Python script であるためテスト必須。

| 対象                     | 検証内容                                                                     |
| ------------------------ | ---------------------------------------------------------------------------- |
| ファイル不在             | `load` / `section` が空 dict を返し、エラー・警告を出さない                  |
| 複数セクションの併記     | 各セクションが独立に取り出せる。他セクションの内容が混入しない               |
| 未知セクション           | 既知セクションの読み取りに影響しない                                         |
| 解析不能な構文           | `SettingsError` になる。メッセージに行位置が含まれ、設定本文の全文を含まない |
| コメント・空行           | 無視される                                                                   |
| 対象外構文（アンカー等） | 解析不能として扱われる                                                       |

テストは `tests/forge/scripts/` 配下に置き、fixture はテストファイル内の文字列定数で持つ。
