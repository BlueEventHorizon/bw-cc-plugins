# REQ-028 文書体系 要件定義書

## 1. 概要

本プロジェクトが扱う文書の体系を定める。どの種類の文書が存在し、どう識別し、どこに配置し、どう参照するかを規定する。

体系が定まっていないと、同じ内容が複数の文書に散り、どれが正しいかを読み手が判断できなくなる。識別子が衝突すれば参照が別の文書を指す。配置が揺れれば文書を探せない。本要件はこれらを防ぐ。

### 1.1 対象システムの性質

forge プラグイン内部および本プロジェクトの文書運用であり、外部公開・本番運用・個人情報の保持を伴わない開発支援ツール相当のスコープである。

## 2. 前提条件

- 文書の配置は `.doc_structure.yaml` が宣言する（[REQ-001 オーケストレータパターン要件](REQ-001_orchestrator_pattern.md)）
- 文書 ID の採番は forge の `next-spec-id` スキルが行う

## 3. 機能要件

### FNC-001: 文書識別子

ID を持つ文書は、プレフィックスと番号の組（`{PREFIX}-{NNN}`）で識別されること。

- 番号はグローバルであり、他のコンポーネントの番号と重ならないこと
- プレフィックスが異なれば別の番号列とすること

理由: 番号が重複すると、参照が複数の文書を指し、どちらを読むべきか判断できない。

### FNC-002: 横断仕様の識別

複数のコンポーネントで共有する仕様は、特定のコンポーネントに属さない形で識別・配置できること。

理由: 共有される仕様が特定のコンポーネント配下に置かれると、そのコンポーネントの所有物と読まれ、他のコンポーネントから変更できなくなる。

### FNC-003: 識別子の採番

新規の文書 ID を手動で決めないこと。採番はスキルを経由して行うこと。

理由: 並行して作業するブランチが同じ番号を選び、別内容の文書が同一 ID で衝突する。衝突はマージ時まで検出されない。
