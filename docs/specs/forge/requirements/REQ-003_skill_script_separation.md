# REQ-003 SKILL.md と script の責務分離要件

## 1. 背景

SKILL.md は AI が tool 呼び出しの都度ロードする常駐コンテキストである。script 固有の情報 (引数列挙・状態遷移規則・JSON スキーマ・誤用禁止警告) が SKILL.md に混入すると AI の判断領域を圧迫し、タスクと無関係な認知負荷が増える。

一方、SKILL はオーケストレーターとして進行管理・判断分岐・ユーザー対話を担う。これらを一律に script へ移すと、自然言語の解釈や利用者に見える進捗報告まで決定論的処理へ押し込み、REQ-001 の責務境界と矛盾する。

SKILL.md のコマンド例は、決定論的なプログラムではなく AI が解釈して実行する指示である。減らすべきものは flag や引数の個数ではなく、AI が実行時に選択・導出・組み合わせる必要がない **未決定の意味的選択** である。名前付き引数が実行時データの意味を明確にする場合もあり、構文形式だけでは認知負荷を判定できない。

複数 SKILL が同じ処理を使う場合、実体ロジックはプラグイン共通の低レベル script に集約する。一方、各 SKILL に決定済みの値を束縛し、公開する操作を必要範囲へ狭める入口は SKILL 配下に置く。これにより、共通領域を汎用処理だけに保ちながら、各 SKILL は自身の文脈だけで呼び出せる。

## 2. 目的

SKILL.md はユーザー意図の解釈、進行管理、現在状態に基づく分岐、ユーザー対話を保持する。script は固定値の適用、機械的な導出・変換・検証、決定論的処理を担う。

各場面で呼び出す操作と固定値を事前に確定し、AI がその場で自由に選ぶ意味的な選択肢を残さない。前段の結果やユーザー入力として自然に得られる実行時データは、意味が明確な契約で script へ渡す。

各 SKILL は、SKILL 固有値があらかじめ束縛され、必要な操作だけを公開するローカルな入口を持つ。同じ低レベル script を使う SKILL 間で薄いラッパーが類似しても、AI の判断領域、SKILL 間の依存、共有領域への SKILL 固有値の混入を増やさないことを優先する。

## 3. 要件

### FNC-001: SKILL.md の clean state

SKILL.md に残してよい情報:

- ユーザー意図の解釈と対話方針
- 全体の進行管理と、現在状態に基づく意味的な分岐
- 各場面で確定した操作の呼び出し
- 利用者へ届ける必要がある進捗・診断情報の読み取りと報告

SKILL.md に書かない情報:

- 固定値・固定方針の選択肢
- 他の入力から機械的に導出できる値の組み立て手順
- script 内部だけで完結する状態遷移・検証規則・完全な JSON スキーマ
- 「別の script を直接呼ぶな」型の禁止警告
- 誤用シナリオの列挙
- 同一場面で自由に組み合わせられる複数の操作・flag 候補

### FNC-002: 入力の責務分類

script の入力は、値の由来に応じて次の責務へ分ける。

| 入力の種類                                         | 責務                                             |
| -------------------------------------------------- | ------------------------------------------------ |
| SKILL 名・category・文書種別等、SKILL 固有の固定値 | SKILL ローカルの操作入口で束縛する               |
| 他の入力・設定・環境から一意に導出できる値         | script が導出する                                |
| ユーザー入力・前段結果として自然に得られる値       | 実行時データとして script へ渡す                 |
| ユーザー意図や現在状態の解釈を要する値             | SKILL が判断し、その場面で呼び出す操作を確定する |

位置引数と名前付き引数は、実行時データの意味と取り違え防止を基準に選ぶ。flag の有無を合否基準にしない。ファイル一覧や JSON の手組みなど、決定論的に生成できる複雑な入力を AI に組み立てさせない。

### FNC-003: 1 場面 1 確定済み呼び出し契約

AI が同一場面で「何を呼ぶか」「どのオプションを組み合わせるか」を自由に選ぶ余地を残さない。

- SKILL.md の各場面で呼び出し全体が一意に確定している
- 同一場面で競合する意味的 operation は別の操作入口に分離する
- 同一資源の順序付き位相は、現在状態から操作が一意に決まる場合、同じ入口の明示モードとしてよい
- 前段で得た値の有無によって必要な引数が確定する構造は、自由な組み合わせとは扱わない

### FNC-004: 誤用防御の配置

誤用の再発防止は以下の順で責務を配置する。

1. script 内部のガード (最優先)
2. script のエラーメッセージ (ヒント提示)
3. script の docstring / `--help`
4. `plugins/forge/docs/` 配下の Just-In-Time 参照文書

SKILL.md での禁止警告は使わない。警告文は AI に禁止対象の存在を認識させ、逆効果になりうる。

### FNC-005: 実測ベース

- 仮想の問題で refactor しない
- 対象は実際に SKILL.md 上に存在するノイズ (flag 露出・禁止警告・多引数呼び出し等) に限る
- 合否は目視レビュー + grep による Yes/No 判定。定量的な baseline 固定・再計測による達成率判定は行わない

### FNC-006: SKILL ローカル操作境界

- 複数 SKILL が再利用する実体ロジックは、プラグイン共通の低レベル script に置く
- SKILL によって一意に決まる値は、各 SKILL 配下のラッパーに束縛する
- ラッパーは、AI がその場で自然に持つ実行時データだけを受ける
- ラッパーは低レベル CLI の全引数を無条件に透過せず、当該 SKILL が必要とする操作だけを公開する
- 同じ低レベル script を呼ぶラッパーが複数 SKILL に存在し、固定値以外が同一でも、SKILL ごとにローカル配置する
- 共通化によって AI に SKILL 名・category・固定方針の選択を戻す構造や、他 SKILL 配下への依存を作らない

この重複は、実体ロジックの重複ではなく、SKILL ごとに決定済みの呼び出し契約を固定するための境界である。SKILL の独立性とは、低レベル実装を複製することではなく、他 SKILL の内部構造や固定値を知らずに自身の操作入口を呼べることを指す。

継承型 SKILL を `Skill` ツールで起動する経路には、固定値を束縛する Python ラッパーを介在させられない。この場合、**呼び出し元 SKILL.md 自体をローカル操作入口**として扱い、外部 SKILL の起動箇所に固定値をリテラルで記述する。固定値を候補・プレースホルダ・ユーザー入力として提示せず、呼び出しごとに完全な起動契約を確定する。同じ固定値が異なる外部 SKILL の起動箇所に現れることは、各起動契約を自己完結させるための重複であり、script ラッパーへ移してはならない。

## 4. 適用対象

forge プラグインの全 SKILL.md と全 script (共有 / SKILL 固有とも)。

## 5. 非目標

- ラッパー script 数の最小化
- SKILL ごとの薄いラッパーの重複排除
- 共有ラッパー層の新設
- 統一エントリーポイント (単一 wrapper から全 operation を dispatch する構造)
- flag 数・位置引数数・script 数による構造品質の判定
- 定量目標値の固定
