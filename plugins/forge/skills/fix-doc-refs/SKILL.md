# fix-doc-refs

このスキルは**参照の実在性の検査と、移動先が決まる参照切れの置換だけ**を行う。親が依頼している
他の作業を引き継いではならない。

直せるかどうかは、**その参照が何を指していたかの答えを誰が持っているか**で決まる（REQ-023 FNC-013）。

| 答えの所在                               | 直し方                                              |
| ---------------------------------------- | --------------------------------------------------- |
| 文書集合（索引から導ける）               | script が置換先を決め、`Edit` で書き込む（Phase 4） |
| このセッションで自分（AI）が変更した記憶 | **その記憶で直す**（Phase 5）                       |
| どこにも無い                             | 報告で終端する（Phase 5）                           |

**索引から導ける置換先を自分（AI）で考えてはならない。** それは script が返す。返らなかった
ものを読解で埋めると、参照は解決するのに指し先が誤っている状態になり、検査がその嘘を保証する
側に回る。参照切れは壊れて見えるが、誤接続は正しく見える。

**ただし、索引が答えを持たないものでも自分（AI）が答えを持っている場合がある。** このセッション
で次のいずれかを行ったのが自分（AI）であれば、答えを持っている。

| このセッションで行った変更         | 自分（AI）が知っていること     |
| ---------------------------------- | ------------------------------ |
| 節・見出しの移動（位置指定の変更） | 移動先の節番号・見出し         |
| ファイルの移動（パスの変更）       | 新しいパス                     |
| ファイル名の変更（改名）           | 新しい名前                     |
| ファイル・節の削除                 | 内容を他へ統合したか、消したか |

削除の場合、参照を差し替えるか消すかは内容の行き先で決まる。他の文書へ統合したのであれば、
自分（AI）はその行き先を知っているので差し替える。内容ごと消したのであれば、参照を残す意味が
無くなったかどうかは利用者の判断であり、報告で終端する。

**根拠にできるのは「このセッションで自分（AI）がその変更を行った」ことだけである。** 参照元や
参照先の記述からの推測、節番号の近さ、残っている節の数は、いずれも根拠にならない。自分（AI）が
変更したかどうかが判別できないなら、変更していないものとして扱う。

## 何を検査するか

参照先が「検査時点で追跡下にあるか」だけを判定する。**git 履歴・他ブランチ・削除済み・未追跡は
実在として扱わない**。参照を辿る読み手が到達できるのは、その時点の追跡下のファイルだけである。

| 検査する参照の形            | 判定                                         |
| --------------------------- | -------------------------------------------- |
| リンク記法                  | 参照元からの相対パスで解決したファイルの実在 |
| 参照リンク（`[x][ラベル]`） | 同一文書に定義行があること、その参照先の実在 |
| 文書 ID の節参照            | 文書の実在と、指した節番号の実在             |

**検査しないもの**: 参照の記法が正しいか、参照先の内容が参照元の主張を裏付けているか、参照先が
変更されたか。いずれも実在性とは別の関心事である。

**リンク記法は Markdown にのみ適用する。** 実装コード・テストから拾うのは文書 ID の節参照だけである
（添字アクセス `d["a"]["b"]` が参照リンクに見えるため）。

## Phase 1: 索引対象の解決

「何を実在する文書とみなすか」は `.doc_structure.yaml` が決める。**パスを推測せず、既存スクリプトに
解決させる**。

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/doc_backend/prepare_advisor_index.py" specs --no-format
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/doc_backend/prepare_advisor_index.py" rules --no-format
```

応答の `root_dirs` と `exclude` を Phase 3 の引数へそのまま渡す。`status` が `success` でない場合は、
`.doc_structure.yaml` の不備として利用者へ報告し、既定値で補って進めない。

**`--no-format` を必ず付ける。** 同 CLI は既定で dprint を実行して索引対象の Markdown を整形する
（doc-advisor の `index-docs` が整形後の本文で `body_hash` を打つため）。本スキルが書き換えるのは
置換先が決まった参照だけであり、走査範囲全体が整形されると置換の差分に無関係な変更が混ざる。
整形は commit 時と索引更新時に走るので、検査側で行う必要がない。

この CLI を使うのは、`.doc_structure.yaml` の展開前の `root_dirs` / `patterns.exclude` を返す CLI が
他に無いためである（`resolve_doc_structure.py --type` は展開済みのファイル一覧を返す）。

## Phase 2: 走査対象の決定

参照元（どのファイルに書かれた参照を検査するか）は索引対象と別である。実装コードのコメントにも
文書 ID の節参照が書かれるため、コードも対象に含める（REQ-023 FNC-005）。

引数 `--scan` が指定されていればそれを使う。指定が無い場合の既定は次のとおり。

- Phase 1 で得た `root_dirs`（プロジェクトが文書と認めている範囲）
- 配布物の置き場（プラグインのディレクトリ）

**テストは既定に含めない。** テストは書式そのものを素材として持つため、参照でない文字列
（`DES-999 §1` のような架空の ID・書式例の節番号）が構造的に多く現れ、参照切れとして報告される。
実測で 4 件の誤検出が出ており、REQ-023 FNC-004 が禁じる形である。

FNC-005 が要求しているのは**参照元をあらかじめ文書ファイルに限定しないこと**（対象に含めうること）
であり、既定でどこを走査するかは呼び出し側の決定である（DES-081 §2）。テストの中の参照を検査
したい場合は `--scan` で明示的に指定する。

## Phase 3: 実行

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/doc_reference/check_refs.py" \
  --index-dirs-json '<Phase 1 の root_dirs>' \
  --index-exclude-json '<Phase 1 の exclude>' \
  --scan-dirs-json '<Phase 2 で決めた走査対象>'
```

終了コードは `0` = 所見なし、`1` = 所見あり、`2` = 検査そのものが失敗。**`2` を「所見なし」として
扱ってはならない**（検査を通したという事実が何も保証しなくなる）。

## Phase 4: 置換

`check_refs.py` が返した `findings` を 1 件ずつ `fix_refs.py` へ通し、置換先が返ったものだけを
`Edit` で書き換える。**置換先を自分で考えない**——決めるのは script である。

```bash
python3 -c '
import json, sys
sys.path.insert(0, "${CLAUDE_PLUGIN_ROOT}/scripts/doc_reference")
import fix_refs
report = json.load(open(sys.argv[1]))
out = [r for r in (fix_refs.determine_rewrite(f) for f in report["findings"]) if r]
print(json.dumps(out, ensure_ascii=False, indent=2))
' <Phase 3 の JSON を保存したファイル>
```

返るのは `{file, line, old, new}` の配列である。各件について、`file` の該当箇所の `old` を `new` へ
`Edit` で置換する。`old` が空配列で返った場合は置換対象が無い（すべて決まらないもの）。

`fix_refs.determine_rewrite` が置換先を返すのは、参照先の basename を持つ実在パスが 1 件だけの
場合（`moved_link`）である。`missing_section` は常に `None` を返す——旧節番号から現節番号への
対応をどの索引も持たないため。

## Phase 5: 報告

置換した件数と、置換しなかった所見を分けて示す。**種別を混ぜない**——対処が異なる。

| 種別              | 意味                                                 | 対処                      |
| ----------------- | ---------------------------------------------------- | ------------------------- |
| `broken_link`     | パスとして解決せず、その名前を持つ文書も実在しない   | 参照の削除・差し替え      |
| `moved_link`      | パスとして解決しないが、その名前を持つ文書は実在する | **候補 1 件なら置換済み** |
| `missing_anchor`  | 参照先の文書は実在するが、そのアンカーが実在しない   | アンカーの修正            |
| `missing_label`   | 参照リンクのラベルに定義行が無い                     | 定義行の追加              |
| `missing_doc`     | その文書 ID を持つ文書が実在しない                   | 参照の削除・差し替え      |
| `missing_section` | 文書は実在するが、その節番号が実在しない             | 自分が動かしたなら直す    |
| `ambiguous`       | 参照が複数の文書に当たり一意に決まらない             | 参照の表記を長くする      |
| `undecidable`     | 解決規則を持たない、または索引が無く判定できない     | 人が確認する              |

解決の対象外とした参照（外部 URL 等）は所見ではない。`out_of_scope_summary` に種別ごとの件数が
出るので、**所見と混ぜずにその件数を伝える**（REQ-023 FNC-012）。

**`undecidable` を所見なしへ畳み込まない。** 判定していないものを「問題なし」と報告すると、
見逃しがそのまま通る。

**新規に作成してまだ `git add` していない文書へのリンクは、参照切れとして報告される。** 索引は
追跡下のファイルから作るため、未追跡の文書は実在に含まれない。`git add` してから検査すれば解消する。

script が置換先を返さなかった所見について、**このセッションで自分（AI）がその変更（移動・改名・
削除）を行ったかを確かめる**。行っていれば答えを持っているので `Edit` で直す。行っていなければ、
参照元の位置・書かれた参照・なぜ置換先が導けなかったかを示して報告で終端する（利用者の指示を待つ）。

### 置換後の再検査 [MANDATORY]

置換を 1 件でも行ったら、**Phase 3 を同じ引数で再実行する**。置換前の結果を根拠に「直った」と
判断しない。再検査で件数が減っていない・別の所見が増えている場合は、置換が誤っていたものとして
扱い、その旨を報告する。

## 禁止事項

| 禁止                                                           | 理由                                              |
| -------------------------------------------------------------- | ------------------------------------------------- |
| script が返さなかった置換先を自分で決めて書き換える            | 参照は解決するのに指し先が誤っている状態を作る    |
| `missing_section` の節番号を推測して張り替える **[MANDATORY]** | 旧→新の対応は索引に無い。番号の近さは根拠ではない |
| 参照を削除して参照切れを消す                                   | 依存の記録が失われる。削除は利用者の判断で行う    |
| 参照先のファイル・見出し・節を作って参照切れを消す             | 文書集合そのものの変更であり、置換の範囲外        |
| 置換前の検査結果を根拠に「直った」と報告する                   | 変更を反映した実体で検証していない                |
| 終了コード `2`（検査失敗）を所見なしとして扱う **[MANDATORY]** | 検査を通した事実が何も保証しなくなる              |
| `undecidable` を報告から落とす                                 | 判定していないものが「問題なし」に見える          |
| 走査対象・索引対象のパスを推測して書く                         | `.doc_structure.yaml` の解決結果と食い違う        |
