# アジェンダ表示構造リファレンス

このファイルは `agenda_render.py` が生成する `agenda.html` の構造を説明する参照文書である。**保存形式ではない**。この文書の書式に従って討議ファイルを手動作成・編集する運用はない。

記録の実体は `agenda_store.py` が管理する JSON であり、`agenda.html` はそこから毎回生成される提示物である（`agenda.html` 本文にも「手編集しても保存されない」旨の生成物注記が表示される）。

## 全体構造

`agenda.html` は次の要素で構成される。

- `<head>`: `<meta charset="utf-8">`・`<title>アジェンダ: {identity}</title>`・`<style>` によるスタイル定義（ドット・バッジ等の配色を含む）
- `<h1>`: アジェンダ全体のタイトル（`アジェンダ: {identity}`）
- `.generated-notice`: 生成物であることを示す注記（生成日時を含む）
- `#agenda-summary` テーブル: 項目一覧。列は ID・項目・重要度・状態・結果・課題（「状態」欄は独立フィールドではなく、下記「状態表示」の3状態導出をそのまま表示する）
- `<section id="item-{ID}" data-changed="...">`: 項目ごとの節。項目数だけ並ぶ
  - `.gutter` 内の `.state-dot`: 変更箇所の表示（下記「状態表示」参照）
  - `<h2>`: `[ID] 項目名` に続けて重要度バッジ（設定時のみ）
  - `<p>`: 背景・本質・決着の3行

## 状態表示

項目は独立した「状態」フィールドを持たない。背景・本質・決着（結論）の記入有無から次の3状態を導出する。

| 状態       | 判定条件                                   | 表示文言                                                             |
| ---------- | ------------------------------------------ | -------------------------------------------------------------------- |
| 未着手     | 背景・本質のいずれも空                     | 「未着手」                                                           |
| 進行中     | 背景・本質のいずれかが非空、かつ結論が無い | 「進行中」                                                           |
| 決着／棄却 | 結論が記録されている                       | 結論の内容をそのまま表示（「決着」「棄却」等、呼び出し側の自由記述） |

判定は背景→本質→結論の順に記入されるという対話の進行と対応している。

変更箇所は、カード全体の背景色ではなく `<section>` 左側余白（`.gutter`）の小さなドットに集約して示す。ドット自体（`.state-dot.changed`）は常に出力されており、実際に可視・不可視を切り替えるのは `<section>` タグが持つ `data-changed` 属性である（CSS の属性セレクタ `section[data-changed="true"] .state-dot.changed` 等が、属性の値に応じてドットの配色を切り替える）。

- `data-changed="true"`: 直前の更新で変わった項目

「今対話中の項目」の表示は持たない。人間は生きた対話そのものから「今何を話しているか」を把握できるため、別途表示層へ伝える必要がないという設計判断による。

## 重要度バッジ

項目見出しの重要度バッジ（パステル配色 + テキストラベル）は、重要度を表すフィールドが設定されている場合にのみ表示される。設定されていない場合、バッジ要素自体が出力されない。バッジの値は呼び出し側が渡した文字列そのままであり、この機構は値の意味（重要度の順序等）を解釈しない。`critical`/`major`/`minor` の3値には専用のパステル配色（赤系・黄系・緑系）が対応し、それ以外の値は既定の配色にフォールバックする。

## 問題・推奨欄

項目節の「問題」（何が問題か・何を決めたいのか）と「推奨」（選択肢と帰結を踏まえた推奨 + 確信度）は任意フィールドであり、記入があるときだけ行が表示される（空のラベルチップは並ばない）。「問題」はアジェンダ開始時に項目とともに渡され、「推奨」は決定モードで背景・本質と同じ record で渡される。

## 決着欄

アジェンダ表の「結果・課題」列（`_result_summary()`）と項目節の「決着」行（`_decision_text()`）は、判定条件が異なる。「結果・課題」列は `decision.outcome` が設定されていれば表示し、未設定なら `-` を表示する。`decision.outcome` と `decision.reason` の両方が設定されている場合は `outcome: reason` の形式で連結して表示する（`decision.reason` 単独では表示の有無に影響せず、`decision.outcome` が無ければ `decision.reason` があっても `-` のままである）。「決着」行は `decision.outcome` が無くても `decision.reason` があればその内容を表示し、両方とも無い場合のみ `(未定)` を表示する。`decision.outcome` と `decision.reason` の両方が設定されている場合は `outcome（reason）`（全角括弧）の形式で連結する——「結果・課題」列の `outcome: reason` とは異なる書式である。そのため `decision.reason` のみを記入し `decision.outcome` を記入していない場合、「決着」行には内容が表示されるのに「結果・課題」列は未記入用の `-` のままになる、という非対称が生じうる。

## 表示の更新

`agenda.html` は生成専用ファイルである。書き込み系コマンド（本文を変える操作）が成功するたびに、`agenda.json` の内容だけから世代番号ファイル `agenda_state.js` とともに毎回まるごと再生成される。読み取り専用コマンドは再描画を伴わない。**開いているブラウザタブは世代番号の変化を数秒ごとに検知し、変化したときだけ自動で全体を再読み込みする**（スクロール位置は保持される）。利用者が手動で再読み込みする必要はない。

ブラウザでの初回表示は、対話開始直後の1回だけ自動的に開かれる。2回目以降は自動で開き直されず、開いたタブが上記の自動追従で最新状態を保つ。

## ID 振り直し・削除操作を機構が提供しない

ID を後から振り直す操作、状態が「取り下げ」「対象外」の項目を削除する操作は、コマンド体系（開始・記録・次項目取得・未決着一覧取得・終了の5コマンド）が提供していない。

## decision を含まないパッチは決着済み項目の記入欄チェックを経由しない

記入欄の検証（背景・本質・結論の非空チェック等）は、差分パッチが結論（decision）を含む場合にのみ働く。既に決着済みの項目に対し、結論を含まない差分パッチ（例: 背景だけを変更するパッチ）を送ると、そのパッチは検証を経ずに反映され、既存の結論はそのまま残る。この経路では「決着済みなのに背景が空」という、結論を経由した更新では起こり得ない状態を作れてしまう。これは機構が機械的に強制していない挙動であり、呼び出し側が意図せず記入欄を空にしないよう注意する必要がある。
