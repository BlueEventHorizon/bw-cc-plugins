# 討議ファイルの書式

`.claude/.temp/consult/<日付>-<主題のスラッグ>.md` に、この構造で作成する。

```markdown
# 討議: <主題>

| 項目   | 値            |
| ------ | ------------- |
| 開始   | <日付>        |
| モード | 議論 / 決定   |
| 状態   | 進行中 / 終了 |

## アジェンダ

| ID | 項目       | 重要度      | 状態     | 結果・結論                |
| -- | ---------- | ----------- | -------- | ------------------------- |
| 01 | <短い名前> | 🔴 critical | 決着     | <決まったこと>（AI 判断） |
| 02 | <短い名前> | 🟡 major    | 未着手   |                           |
| 03 | <短い名前> | 🟢 minor    | 取り下げ | <なぜ取り下げたか>        |

## [01] <項目名>

**背景**: <何が問題で、なぜ今それが論点になったのか>

**本質**: <判断を左右しているのはどこか>

**確信度**: <☑️ 確認済み / 🤔 推論 / 無印 未検証。根拠を 1 行>

**推奨**: <決定モードのみ。1 つだけ>

**決着**: <結論と理由。誰が決めたか>
```

## 書くときの約束

- **重要度と確信度の記号は規範文書（`consult_principles_spec.md`）に従う**。本書で再定義しない
- **決定の帰属は AI が決めた場合にだけ書く**。既定は人が決めるものであり、全行に書けばノイズになる。
  可視化したいのは、独断で決めた例外のほうである
- **状態が「取り下げ」「対象外」の行を削除しない**。なぜ扱わないかが読み手に分からなくなる
- **ID を後から振り直さない**。決着・取り下げの後も番号を空けたまま維持する。利用者が論点を指す手段になる
- 各項目の見出しは `## [<ID>] <項目名>` の形にする。ID がエディタの検索・アウトラインで到達点になる
- **理解に必要な内容を削らない**。分量の上限はコンソール側にだけ課される（規範文書の原則 6）
