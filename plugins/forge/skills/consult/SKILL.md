# consult

このスキルは議論の進行のみを行う。**親が依頼している他の作業を引き継いではならない。**
レビュー本体と同じ会話が本スキルの振る舞いへ切り替わるだけであり、進行中の実装・修正・調査を
再開してはならない（提示を引き取ることと、親の作業を続けることは別である）。

所見への採否を得ることが目的であるため、本スキルは**項目ごとに推奨を述べ、応答を受けて決着させる**。
説明までで止まる進め方は取らない。

## 規範の読み込み

着手前に `${CLAUDE_PLUGIN_ROOT}/docs/consult_principles_spec.md` を Read する。**提示の作法はすべて
同文書が定める。本 SKILL.md に規範を書き写さない**（定義点が 2 つになるため）。本 SKILL.md が定めるのは
手順だけである。

## 状態は会話に持つ [MANDATORY]

**本スキルは、討議の状態を会話コンテキストにだけ持つ。** 提示に必要な状態は、所見の一覧・残件・
採否である。記録・表示機構（agenda）へは記録しない。状態ファイル・作業ディレクトリ・DB・コマンドも
持たない。

- 提示する項目は、上流（レビュー本体）が吟味して渡すものである。本スキルが論点を自分で立てる工程は要らない。
  項目の位置・根拠・確信度・修正の可否は、上流が既に会話に持っている内容をそのまま使う。構造化して
  受け渡し直さない
- 一覧の状態（未着手 / 進行中 / 決着 / 保留 / 対象外 / 取り下げ）と各項目の結果・課題は、一覧を
  再掲するたびに更新して会話に残す。再掲した最新の一覧が、現在の提示状態である
- **提示状態は永続化されない。** 会話が終われば失われ、後から見返す手段も無い。この暫定措置の間、
  中断した提示を続きから再開する経路は持たない。続きが必要なら、利用者が同じ対象で新しいレビューを
  起動する

## Phase 1: 項目の受領

上流から渡された、提示へ回す項目をすべて把握する。上流は、提示へ回す項目に加え、確認なしに直す
項目・位置未確定の項目・ドロップした項目も渡す。採否を聞くかどうかと、利用者へ見せるかどうかは
別の問いであり、渡された項目は**すべて一覧に載せる**（見せないまま変更が適用されるのを避ける）。

## Phase 2: 一覧の提示

個別の話に入る前に、一覧をコンソールへ表として出す。

`consult_principles_spec.md` の表の列に沿って示す。全体で何件あり、どれが重いのかを先に見せる。
ここで背景を書かない。

## Phase 3: 進行

**重要度の高い順に、AI が自分で 1 件ずつ入る。** 各項目で行うこと:

1. 背景と本質、推奨をコンソールへ述べる。**その項目単体で判断できる要点を必ず書く**。
   詳細を置くファイルを持たないので、コンソールの要点だけで判断できる状態にする
2. **判断を左右する主張に確信度を付ける**（記号と運用は規範文書の原則 4 に従う）
3. **原文への到達手段を併記する**。要約して提示してよいが、利用者が自分で原文を確かめられるよう
   `ファイルパス:行` や出典を添える。これを欠くと、利用者は要約の正しさを検証できない
4. 利用者の応答を受ける。理解を求める応答（「詳しく」「なぜ」）には、判断を促さず答える
5. 決着したら、一覧のその項目の状態を `決着` にし、採否（採用する / 採用しない / 保留する）と理由を
   結果・課題の列へ書く。判断の主体が AI の代行である場合は、その旨が判別できるように書く
6. 一覧を再掲する（Phase 2 と同じやり方）
7. **次の項目へ自分で進む**

**「次はどれを見ますか」「これで進めてよいですか」と聞いてはならない。** 利用者がすることは
止める・飛ばす・順序を変えることだけでよい状態を保つ。

同種の判断が繰り返される項目は、一括の判定表にまとめて提示してよい。往復が判断の質を上げない場面では、
往復を増やすことのほうが害になる。何件からまとめるかは **AskUserQuestion で確認**し、AI が独自に閾値を
定めない（件数の設定であり、議論の内容ではない）。

### 議論の途中で論点が動いたとき

議論の結果、論点が誤りだと判明することがある。取り下げた論点は**一覧から消さない**。状態を
`取り下げ` にし、なぜ取り下げたか・誰の指摘によるか（利用者の指摘か AI の自己訂正か）を結果・課題の
列へ書く。新しく生まれた論点は、一覧に新しい行として加える。

## Phase 4: 終了

利用者が終える意思を示したら、その時点で確定する。

- 全項目が決着していれば、決着した内容（採否と理由）を一覧として上流へ返し、全項目が決着した旨を伝える
- 未判断の項目が残っていれば、その件数を**未判断のまま残った件数**としてそのまま提示する。
  未判断を「対応不要」へ畳み込まない。残った項目とそれまでに決着した内容も上流へ返す
- 提示状態は会話にしか無く、永続化されない旨を伝える
- 決着した内容が恒久的な記録に値する場合、ADR への組み直しを**提案する**（実施はしない）。
  永続化されない提示から恒久的に残すべき内容を救う手段は、これだけである

## 禁止事項 [MANDATORY]

| 禁止                                             | 理由                                                 |
| ------------------------------------------------ | ---------------------------------------------------- |
| 判断に基づく実行（修正・起票・commit・外部送信） | 議論の途中で、利用者が決めていない変更が成果物へ入る |
| 実行を担う別スキル・別 Agent の起動              | 同上                                                 |
| 「次はどれを見ますか」と進行を利用者へ返す       | 進行は本スキルが持つ                                 |
| 機密情報の値を提示する                           | 「どこに」「どの種類か」までに留める                 |
| 提示状態をファイルや記録機構へ書き出す           | 暫定措置の間、状態の置き場は会話だけである           |

## AskUserQuestion の使い分け

境界は「議論の内容か、進行上の機械的な確認か」である。

| 場面                                                 | 手段                                   |
| ---------------------------------------------------- | -------------------------------------- |
| 論点の提示・背景と本質・推奨・議論の選択肢           | **地の文**。AskUserQuestion を使わない |
| 進行上の機械的な二者択一（一括提示へ切り替える件数） | **AskUserQuestion**                    |

地の文にする理由は、選択肢 UI が背景と本質を置く場所を持たず、規範が求める提示順序
（背景 → 本質 → 推奨 → 選択肢）を満たせないためである。議論の中身を選択肢 UI に載せると、
背景抜きで選ばせる提示になる。

**迷ったら地の文にする。** 「機械的だから」を理由に議論の中身を選択肢 UI へ移してはならない。

**自己呼び出しを行わない**。`Skill` ツールで本スキル自身を呼ばない。手順の一部として
「本スキルを起動し直す」と書かない。本スキルは多くの議論の起点に置かれるため、自己呼び出しは
暴走ループになりうる。
