# onboarding — 規範をどこに置くか

onboarding は 2 つのことをする。forge の規範文書を全件読ませること（SKILL.md の Phase 1）と、規範の一部を利用プロジェクトの CLAUDE.md へ転記すること（Phase 2）。**転記してよい範囲を決める基準**がこの文書の主題である。

## 三層

| 層                                          | 中身                                   | 強制力                                                 |
| ------------------------------------------- | -------------------------------------- | ------------------------------------------------------ |
| COPY 範囲（[copy_block.md](copy_block.md)） | forge が破綻しないために必須の規範だけ | 強制。転記先の CLAUDE.md に載り、毎リクエスト読まれる  |
| 内蔵 docs（[docs/](../../docs/)）           | forge の規範・推奨                     | プロジェクトが別のルールを定めれば、そちらが優先される |
| 転記先 CLAUDE.md のマーカー外               | そのプロジェクトが自分で決めたこと     | そのプロジェクト内では強い                             |

## forge が決めてよい範囲

開発プロジェクトには固有のやり方がある。forge が決めてよいのは、**forge を使う以上、守られないと forge が破綻する内容だけ**である（文書 ID を手で採番すれば並行ブランチで衝突する。frontmatter を手書きすれば索引が信頼されない）。プロジェクトが自由に決めてよいことを forge は強制しない。文書スタイルの好み・議論の作法・分野別の数値カタログは、たいていそちら側である。

## 上書きが成立する仕組み

内蔵 docs の規範と、プロジェクトが自分で定めたルールが相反することはある。そのときはプロジェクト側が優先される。相反する規範を読んだとき、生成 AI が後に読んだものを採る傾向を前提にした構造である。

CLAUDE.md は毎リクエストの文脈に入るため、この上書き経路が働かない。**COPY 範囲へ規範を移すことは、プロジェクトが別の流儀を選ぶ余地を奪うことと同じ**である。加えて CLAUDE.md は利用者の目に触れる。だから COPY 範囲は最小に保つ。

**第 2 層が届くのは、読まれたときだけである。** 内蔵 docs に置いても、Phase 1 の必読文書か、それを参照するスキルのどちらかを経由しなければ文脈に入らない。どちらにも載っていない文書の規範は、上書き可能なのではなく単に不在である。COPY 範囲から規範を降ろすときは、降ろした先が読まれる経路を持つかを確かめる。

## 読むことに承認は要らない。書き込むことに要る

転記は**それを実行したセッションには効かない**。CLAUDE.md は起動時に instruction として注入され、途中の書き換えは反映されないため、`absent` なら開始時にブロックが無く、`stale` なら古いブロックのまま走り切る。ブロックの存在理由は「スキルを経由しない作業でも規範が文脈に入る」ことなので、主機能が 1 セッション遅れて効くことになる。しかも遅れるのは、何も整備されていない初回セッションである。

そこで `--check` は、`fresh` でないとき規範本文（`block_body`）を返す。**承認の可否とは無関係に返す。** 承認が要るのは利用者の統治文書を書き換える行為であって、forge の規範を自分の文脈に入れる行為ではない（Phase 1 が内蔵 docs を無許可で読むのと同じ）。COPY 範囲は「forge を使う以上、守られないと forge が破綻する規範」なので、書き込みを断られてもその契約は成立していなければならない。**断られたのは「私の CLAUDE.md に書くな」であって「その規範に従うな」ではない。**

`stale` のとき、失効した規範は文脈から消えない。どちらが有効かを言わなければ矛盾が残るため、`next` が「開始時に読んだブロックは失効している」と明示する。これは上書きと同じ仕組み（後に読んだものを採る傾向）に乗る。

## COPY 範囲を SKILL.md に置かない

転記元は `copy_block.md` 専用ファイルで、その全文が転記範囲である。**SKILL.md には置かない。** SKILL.md は起動時に全文がコンテキストへ注入されるため、転記済み（`fresh`）のとき、転記範囲は CLAUDE.md に一字一句同じ形で既にあり、SKILL.md 側の複製が必ず二重読みになる。`fresh` の判定はブロック全文の一致で行うので、この重複は推定ではなく確定する。

読み飛ばし指示で回避することはできない。指示に到達した時点で注入は終わっているためである。専用ファイルに分けることが唯一の手段であり、これは規約ではなく構造の帰結である。

同じ理由で、SKILL.md には**実行時に使わない記述を置かない**。COPY 範囲の編集規約（`##` 見出しを `forge` で始める等）は執筆者向けであり、この README と `update-onboarding-copy` が持つ。status から一意に決まる判定・承認文言・次の行動は `onboarding_block.py --check` が返す。
