# ADR（アーキテクチャ決定記録）デフォルトフォーマット

プロジェクト固有の「ADR フォーマット」が見つからない場合に使用する汎用フォーマット。

作成トリガー（どのようなときに ADR を作成・更新するか）: [design_principles_spec.md](design_principles_spec.md) 「設計書の保守」
違反時の severity: [design_principles_spec.md](design_principles_spec.md) 重大度カタログ「ADR 運用」を参照（本ファイルは severity を宣言しない）

---

## ADR の性質

ADR は**意思決定の記録**であり、設計書と異なり**追記型**の文書である。

- 一度 accepted になった決定の本文（コンテキスト・決定・代替案）は書き換えない
- 決定を覆す場合は**新しい ADR を作成**し、旧 ADR の Status を `superseded` に変更する
- ステータス遷移の記録は歴史的記録の例外として ADR 内に残してよい

---

## ファイル命名規則・配置

```
ADR-{NNN}_{topic}.md
```

- 設計書と同じディレクトリに配置する（ADR 専用ディレクトリは作らない）
- ID は手動で決めず、必ず `next-spec-id` スキルで採番する（`python3 scan_spec_ids.py ADR --share-prefixes ADR,DES`）。ADR と DES は同一ディレクトリで通し番号を共有するため `--share-prefixes ADR,DES` を必ず付与する

例: `ADR-032_path_schema_unification.md`

---

## Status 値 [MANDATORY]

| Status       | 意味                                                          |
| ------------ | ------------------------------------------------------------- |
| `proposed`   | 提案中。まだ実装の根拠にしてはならない                        |
| `accepted`   | 承認済み。現行の設計判断の根拠                                |
| `rejected`   | 棄却。採用しなかった記録として保持する                        |
| `superseded` | 新しい ADR に置き換えられた。備考に後継 ADR ID を必ず記載する |

## テンプレート

```markdown
# ADR-XXX {決定のタイトル}

## メタデータ

| 項目     | 値           |
| -------- | ------------ |
| ADR ID   | ADR-XXX      |
| Status   | proposed     |
| 決定日   | {YYYY-MM-DD} |
| 関連設計 | {DES-XXX 等} |

## 1. コンテキスト

{この決定を迫られた背景・課題・制約を記述。決定の妥当性を後から再評価できる粒度で書く}

## 2. 決定

{採用した選択肢と、その決め手を記述}

## 3. 検討した代替案

| 代替案 | 棄却理由 |
| ------ | -------- |

## 4. 影響

{この決定による帰結。得られるもの・失うもの・新たに生じる制約を正負両方記述}

**変更対象ファイルの具体パス列挙はここに書かない**（CLAUDE.md「文書間参照にパスを焼き込まない」）。ADR は決定とその根拠・帰結を記録する文書であり、決定に至る過程で参照した文書は「メタデータ」の関連設計欄に ID で残す。一方「どのファイルをどう変更するか」は決定そのものではなく実装計画（Issue・plan.yaml）の責務であり、ADR に書くと後のファイル移動・分割で陳腐化する。実装への波及が大きい決定であることを示したい場合は、対象コンポーネント名や種別（例: 「reviewer プロンプト」「plan.yaml マージロジック」）程度の抽象度に留め、詳細は別 Issue の実装計画に譲る。

## 5. ステータス履歴

| 日付         | Status   | 備考 |
| ------------ | -------- | ---- |
| {YYYY-MM-DD} | proposed |      |
```
