## 2. チェック順

「どの委譲先文書から先に読むか」の順序。規範本体は再掲しない:

1. **P1 規範の把握**: [sensitive_information_spec.md](../sensitive_information_spec.md) §2 (含めてはならないもの) → §3 (許容される書き方) → §4 (実在の値を模した例示) の順で読み、判断基準を確定する。プロジェクト固有の取扱規約が解決されている場合は続けて読み、内蔵規範と衝突する箇所はプロジェクト側を採用する
2. **機械検出結果の真偽判定**: 依頼本文に含まれる検出結果の各件について、該当箇所を開いて実体を確認し、真の混入か §3 に該当する false positive かを判定する。**検出結果を根拠にそのまま所見化しない** (スキャンは形式一致のみで文脈を見ていない)
3. **抑制された検出の確認**: 抑制マーカーで分類された件も同様に確認する。マーカーが付いているという事実は、混入でないことの根拠にならない (同 §5.2)
4. **スキャン対象外の混入の捜索 [MANDATORY]**: 機械検出が拾えない混入を対象から自力で探す。スキャンは既知形式にしか一致しないため、この工程を省くとスキャンのパターン網羅性がそのままレビューの上限になる (同 §5.1)。とくに次を見る:
   - 形式を持たないパスワード・内部エンドポイント (§2.2)
   - 散文中に埋め込まれた資格情報 (設定手順・トラブルシュート記述に混ざりやすい)
   - 実在の値を改変した例示 (§4)
5. **P2 矛盾・齟齬**: 検出結果が指す位置と実際の記述が食い違う場合 (行ずれ・既に修正済み等) は、その旨を所見に記す

> **P3 を適用しない理由**: P3 は「より少ない要素 (ステップ・クラス・抽象・分岐) で同じ目的を達成できる代替案の有無」を Yes/No で判定する観点である ([review_priorities_spec.md](../review_priorities_spec.md) §1.3)。混入の有無に代替案という概念が存在しないため、判定しても常に No にしかならない。形式的に回して空振りさせるより、適用対象が無いことを明示する。

## 3. 判定ルール

| recommendation | 採用条件                                                                                                          |
| -------------- | ----------------------------------------------------------------------------------------------------------------- |
| `fix`          | 規範違反であり、修正による副作用が限定的な場合                                                                    |
| `create_issue` | ルール未整備で発見した場合 ([review_priorities_spec.md](../review_priorities_spec.md) §4 の 3 条件をすべて満たす) |
| `skip`         | false positive / グレーゾーン許容範囲内 (principles の許容範囲に該当)                                             |

### 判定に迷う場合

[sensitive_information_spec.md](../sensitive_information_spec.md) §3 のとおり、**判断に迷う検出は混入として扱う** (`skip` にしない)。本種別では false positive のコストと false negative のコストが釣り合わないため、他種別の「グレーゾーンは許容範囲へ倒す」運用を適用しない。

### `recommendation: create_issue` の 3 条件

| # | 条件               | 内容                                                                                                                    |
| - | ------------------ | ----------------------------------------------------------------------------------------------------------------------- |
| 1 | 該当規定なし       | P1 で参照する SSOT (プロジェクト固有 rules / forge 内蔵 principles) のいずれにも該当規定が存在しない                    |
| 2 | 再発性または客観性 | 同種の指摘が今回・過去のレビューで複数箇所に観察される (再発性)、または客観的事実で説明可能 (AI 主観の単発判断ではない) |
| 3 | 明文化可能粒度     | ルールとして明文化可能な具体粒度を持ち、Issue として書き起こせる (「主観的にシンプルでない」等の評価語のみは不可)       |

3 条件のいずれかが不成立の場合は `recommendation: skip` (skip_reason に該当条件不成立の理由を記載) とする。
