# 決定論的な生成物は AI が作らない

## 1. 目的

構造を持つ生成物（データ形式・置き場・ファイル）を AI が組み立てると、それを受け取る側に検査が要る。検査は許可された形だけを通すため、そこに無いものが落ちる。落ちたことは多くの場合、表に出ない。

本文書は、この連鎖を根から断つ原則を定める。

本文書が定めるのは、決定論的に作れるものを実行系が作るという分担と、それによって何が不要になるかである。個別の場面で「これは決定論的に作れるか」をどう判定するかは、プロジェクトの規範に従う。

## 2. 原則

**決定論的に作れる生成物は、AI ではなく決定論的な実行系が作る。**

「決定論的な実行系」は、同じ入力に対して常に同じ出力を返す実行主体を指す。言語・実装形態は問わない（script・関数・コマンド・サービスのいずれでもよい）。

**AI が担うのは内容を決めることだけである。** 形・置き場・書き込みには関わらない。

## 3. なぜそうするか

AI が作ると、次の連鎖が生まれる。

| 段階                    | 結果                                   |
| ----------------------- | -------------------------------------- |
| AI が生成物を組み立てる | 誤りうる                               |
| 誤りうる                | 受け取る側に検査が要る                 |
| 検査が要る              | 通す形をあらかじめ決める（許可リスト） |
| 許可リストがある        | そこに無いものが落ちる                 |
| 落ちる                  | 落ちたことに気づけない場合がある       |

実行系が作れば、この連鎖は最初の段階で消える。形が壊れるのは**バグ**であり、実行時の検査で受け止める対象ではない。バグは直せばよく、直せば再発しない。検査は毎回動き、しかも落としたものを取り戻せない。

## 4. 何が不要になるか

| 実行系が作ると             | 不要になるもの                 |
| -------------------------- | ------------------------------ |
| 形が壊れるのはバグになる   | 実行時の形式検査               |
| 形式検査が要らない         | 許可リスト・スキーマの重複定義 |
| 許可リストが要らない       | 想定外の値が落ちる経路         |
| 置き場を AI が組み立てない | 置き場の取り違え               |
| ファイルを AI が書かない   | 中間ファイルとその後始末       |

**「落ちる」ことの重さ**: 検査に弾かれて失敗が返るなら、まだ気づける。危険なのは、許可リストに無いものを黙って捨てる実装である。呼び出しは成功を返し、失われたことは誰にも見えない。

## 5. 適用範囲

決定論的に作れるものすべてに適用する。次を含む。

- 構造化データ（形式・キー名・入れ子）
- ファイルの置き場とファイル名
- ファイルへの書き込みそのもの
- 識別子の採番
- 列挙・転記・集計

AI から実行系へ内容を渡す経路は、**AI が形を組み立てずに済む形**にする。値だけを渡し、それをどう構造化するかは実行系が決める。

## 6. 適用しない場面

本原則は「何でも実行系へ寄せよ」ではない。次は AI が担う。

- 自然言語の解釈
- 進行の管理と分岐
- 利用者との対話
- 内容そのものの決定（何を書くか・何を判断するか）

これらは決定論的に作れないため、実行系へ移すと成立しない。境界の判定基準はプロジェクトの規範に従う。

### 6.1 AI の応答そのものを構造化データとして受け取る場合

別のセッション・別の Agent として動く AI の応答を、呼び出し側が構造化データとして受け取ることがある。**この場合に限り、受け取る側の検査を置く。**

応答の中身を決めているのは AI であり、代わりに組み立てられる実行系が存在しない。したがって §7 が求める「入力を作る側に置く」を満たす場所が無く、**検査を置ける最も上流が受け取る側になる**。

この例外が及ぶのは応答を受け取る境界 1 つだけである。検査を通った後のデータを、さらに下流で再び検査してはならない（§7）。

## 7. 検査を置く場所

検査が要る場面はある。ただし置く場所は**入力を作る側**であり、受け取る側ではない（作る側が AI であり検査を置く実行系が上流に存在しない場合だけ、§6.1 により受け取る側に置く）。

同じデータに対して検査点を 2 つ持つと、判定が食い違ったとき、上流を通ったものが下流で落ちる。落ちた理由はどちらの検査によるものか分からない。

- 内容の妥当性は、それを判断できる主体が 1 度だけ検査する
- 受け取る側は、渡されたものをそのまま扱う

## 8. 重大度カタログ

| 違反パターン                                                     | 違反時の重大度 | 理由                                                                              |
| ---------------------------------------------------------------- | -------------- | --------------------------------------------------------------------------------- |
| 許可リストに無い入力を、エラーを返さず黙って捨てる               | 🔴 critical    | 失われたことが誰にも見えない。最も検出が遅れる                                    |
| 決定論的に作れる生成物を AI に組み立てさせている                 | 🟡 major       | 検査・許可リストの連鎖を生み、データの欠落経路を作る                              |
| AI が組み立てた生成物を、受け取る側が実行時に形式検査している    | 🟡 major       | 検査が要る状態そのものが、作り手の選択を誤っている兆候（§6.1 に当たる場合を除く） |
| 同じデータに対する検査点が 2 つ以上ある                          | 🟡 major       | 判定の食い違いで、上流を通ったものが下流で落ちる                                  |
| AI がファイルの置き場・ファイル名を組み立てている                | 🟡 major       | 置かれた状況によって書き込み先が変わり、誤っても成功が返る                        |
| 自然言語の解釈・進行管理・対話を決定論的な実行系へ押し込んでいる | 🟡 major       | 決定論的に作れないものを移しており、成立しない                                    |
