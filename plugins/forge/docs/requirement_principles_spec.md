# 要件定義書 作成原則

プロジェクト固有のルールがない場合に参照する汎用原則。
プロジェクト固有のルールがある場合はそちらを優先すること。

テンプレート・frontmatter は [requirement_format.md](requirement_format.md)、設計書との振り分け判定は [spec_design_boundary_spec.md](spec_design_boundary_spec.md) を参照。

---

## 要件定義書の定義

- **責務**: ユーザーの視点で、何を作るかを書く。必要な機能・データ・ルールと、それらがユーザーにもたらす価値。読者はステークホルダー全員
- **書かないもの**: 実装方法（設計書の責務）。ただし既に決まっていて選択の余地が無い事項は、要件定義書に具体的に書く
- **存在期間**: 恒久。ただし不変ではない
- **改訂**: 差分開発によって修正されうる。差分開発の期間中、その範囲の現在の仕様は差分側の要件定義書であり、旧要件定義書の記述は既に置き換わっている。旧側は実装期間中は書き換えず、実装完了後の merge で改訂する（[additive_development_spec.md](additive_development_spec.md) §2・§3・§4）
