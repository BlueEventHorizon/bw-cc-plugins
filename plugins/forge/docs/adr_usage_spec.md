# ADR 利用規範

ADR（アーキテクチャ決定記録）を**根拠に判断する側**の義務を定める。提案・実装・レビューで、過去の決定の棄却理由を根拠に、提案や所見を見送るときに従う。

ADR を書く・直す側の規範は [adr_principles_spec.md](adr_principles_spec.md)、書式は [adr_format.md](adr_format.md) が定める。本書は、ADR を書かない作業でも読む。

---

## 拘束力を持たない

ADR は指示ではなく気づきである。**棄却理由を読んでもなお正しいと判断したなら、提案してよい**。過去の判断が現在の前提の下でも妥当とは限らず、前提が変わったことに気づけるのは提案しようとしている側だけである。

## 読み手の義務

ADR を根拠に提案・所見を見送るときは、次を行う。

- **棄却理由が依拠する前提が、今も成立しているかを確かめる**。成立していなければ、ADR を根拠にしない
- 見送った場合は、根拠にした ADR の番号を添える。番号は、ファイルの番号と節番号で示す（例: `ADR-NNN §N`）。見送りの判断を後から追跡できるようにするためである

## 抑止の到達率は上げない

ADR に書いたことが提案時に必ず読まれる保証はない。到達率を上げる仕組み（全 ADR の事前読み込み等）は**設けない**。ADR は拘束力を持たないため、届かなかったことの損失は「重複した提案が 1 度出る」に留まる。読み込み量を増やす代償に見合わない。

## 重大度カタログ

| 違反パターン                                                   | 違反時の重大度 | 理由                                                           |
| -------------------------------------------------------------- | -------------- | -------------------------------------------------------------- |
| ADR を根拠に提案・所見を見送ったのに、ADR の番号を添えていない | 🟢 minor       | 見送りの根拠が追跡できず、棄却理由が失効していた場合に遡れない |
