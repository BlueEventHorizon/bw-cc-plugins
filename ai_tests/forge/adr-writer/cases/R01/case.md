# R01 判定フロー Phase 順序の転換

- 決定: 本決定は未承認である。以下は提案として記録したものであり、承認を経ていない。判定を「Issue 本文のみで直行可能な判定」と「Phase 4〜5 の調査結果を要する判定」に分離し、直行可能な判定を Phase 2〜5 の前に移動する。適用条件チェック（Phase 6.5）は一方向の早期終了ゲートとし、偽の場合は何も確定させない。Phase 6 判定2・Phase 7 条件3 が Phase 4〜5 の調査結果を要する依存関係は変更しない。各 Phase の挙動は、判定フロー設計書が定めていた。
- 文脈: Foo 判定フローの既存 Phase 構成は、Phase 2〜5（仕様検索・ルール検索・類似変更調査・既存コード調査）を判定（Phase 6〜8）より前に一括実行する。この順序は、明白なケース（例: 不具合修正であることが Issue 本文から一意に判定できる場合）でも、判定確定前に重い調査をすべて終える必要があり非効率である。一方で、判定の一部（追加開発規約の適用条件チェック、要件確定性の判定、リスクゲート条件1・2）は Issue 本文の記述のみで判定可能であり、Phase 2〜5 の調査結果を必要としない。
- 代替案: (1) 適用条件の非適用時にもワンショット実装ルートへ早期確定する: 適用条件が判定する「機能分離管理の要否」と「仕様駆動の要否」は別軸であり、高リスクな不具合修正・リファクタリングを誤ってワンショット実装に確定させる欠陥がある（レビューで検出）ため棄却。(2) Phase 2〜5 すべてを判定確定後に後ろ倒しする: Phase 6 判定2・Phase 7 条件3 が Phase 4〜5 の調査結果を判定の直接根拠として要求するため、判定前に実行する必要があり棄却。(3) 既存の Phase 順序（一括調査→判定）を維持する: 直行可能な判定がある場合でも重い調査を待つ非効率が解消されないため棄却。
