# 文書検索 backend 設計（抜粋）

## backend

Hoge の文書検索は、Foo-index サーバを backend の 1 つとして使う。検索の前に、対象の ENTRY が検索可能かを確かめる。

## ENTRY の状態

| 状態     | 意味                                      | Hoge の動作                        |
| -------- | ----------------------------------------- | ---------------------------------- |
| 整備済み | 索引があり検索できる                      | そのまま検索する                   |
| 未整備   | ENTRY / series が存在しない               | 索引を作成してから検索する         |
| 退避     | ENTRY が退避（`archive_index`）されている | 索引を作成せず、復活操作を案内する |

未整備と退避を取り違えてはならない。両者を判別する手段が要る。

## error の判別

- 検索呼び出しが error を返したとき、`error.data.code` の識別子にのみ依拠して、未整備か退避かを判別する。
- 対象は次の 2 値である。メッセージ文言と数値 code では分岐しない。
  - `ENTRY_ABSENT`: 未整備。索引を作成してよい。
  - `ENTRY_ARCHIVED`: 退避。索引を作成せず、復活を案内する。
- Foo-index サーバは 1.2.1 以上を要求する。1.2.0 以下に向けた、文言一致のフォールバック経路は持たない。

## 判別できない error

- 識別子を読み取れない error は、障害として利用者へ報告する。未整備側へ倒して索引作成を試みることはしない。
