# レビューバックエンド設計（抜粋）

## 構成

- 本体（`modules/review/`）は、対象の確定と所見の統合を担う。
- バックエンドは、`modules/backend-a/` と `modules/backend-b/` の 2 つがある。それぞれレビューを実行して所見を返す。

## 所見の書式

- 所見は、本体とすべてのバックエンドの間で同一の書式で受け渡す。書式は、重大度・位置・本文の 3 要素を持つ。
- 書式の解釈規則（文字列から 3 要素への分解）は、本体とバックエンドのどちらでも必要になる。
- 現状、解釈の実装は `modules/backend-a/scripts/parse_findings.py` にあり、本体が直接これを呼んでいる。
- `modules/backend-b/` は、同じ解釈を自前で行う処理を持たず、呼び出し方を決めかねている。

## 課題

- backend-b をリリースするまでに、解釈の実装の置き場を決める必要がある。
