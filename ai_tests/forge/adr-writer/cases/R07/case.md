# R07 Hoge レビューの Hoge メッセージ基盤への正式統合（分離決定の撤回）

- 決定: Hoge レビューを Hoge メッセージ基盤へ正式に merge し、先行する分離決定を撤回する。仕様統合手順を実行し、Hoge レビューの要件の内容は Hoge メッセージ基盤の要件の該当節（機能要件として採番）へ、Hoge レビューの設計の内容は Hoge メッセージ基盤の設計の該当各節へ統合する。Hoge メッセージ基盤の設計の停止フック記述は、旧 shell 実装（Foo 用・Bar 用の 2 スクリプト）ベースの記述から、本番実装である単一の Python スクリプト（返信ヒント付き）ベースの記述へ更新する。Hoge レビューの専用仕様ディレクトリは統合完了後に削除する。先行する分離決定は削除せず、その決定節へ失効マーカーを付けて撤回の経緯を残す（判断が誤りだったことも含めて記録に残す価値がある）。
- 文脈: 先行する決定は「Hoge メッセージ基盤（汎用通信基盤）と Hoge レビュー（応用レビューシステム）は恒久的に別 feature として維持する」と決定した。根拠は、Hoge レビューの内容（返信ヒント）を Hoge メッセージ基盤の設計書へ merge すると、基盤自体が「レビュー対話専用の仕組み」であるかのように読める記述に変質し、将来の独立した配布・汎用応用可能性を損なう、というものだった。この決定を踏まえて実装・運用を続けたところ、以下の事実が確認された。単一の Python スクリプト（Hoge レビューとして実装したもの）は、Foo・Bar 双方の停止フック登録から実際に呼ばれる本番のフック実装そのものであり、旧 shell 実装を置き換えている。「Hoge メッセージ基盤の上に構築された応用機能」ではなく、基盤のフック実装が Python へ移行しただけである。返信ヒント機能は、レビュー対話に限定される性質を一切持たない。Foo・Bar 間で任意の非同期メッセージを往復する際に、受信側が自己完結的に返信できるようにするための汎用機能であり、基盤の他のユースケースにもそのまま適用できる。先行する決定が懸念した「基盤がレビュー専用に変質する」という問題は、実際には発生しない。返信ヒントは基盤の停止フック契約（差し戻しの理由に何を含めるか）の話であり、レビューという用途に依存する記述を一切含まない。すなわち、先行する決定の前提（Hoge レビューが基盤とは独立した「応用」であり、両者の分離が基盤の汎用性を守る）は誤りだった。実態は「Hoge レビューという別名がついていただけで、中身は基盤そのもののフック実装だった」。影響として、Hoge レビューの要件・設計は基盤の仕様へ統合され、専用の仕様ディレクトリは消滅し、レビュー対話に関する記述の参照先が基盤へ一本化される。実装・テストのディレクトリ構成も仕様に合わせて基盤配下へ移る。
- 代替案: (1) 先行する分離方針を維持し、Hoge レビューを独立 feature のまま残す: 実態（単一の Python スクリプトが基盤の本番フック実装そのものであること）と文書構造が乖離し続け、次に読む人が「基盤とは別に応用機能がある」という誤った理解をするため棄却。(2) 先行する分離決定を削除して無かったことにする: 一度その方針で実装・運用した経緯（frontmatter 改訂・計画破棄等）が記録から失われ、同じ議論を将来繰り返すリスクがある。誤った決定も含めて残す価値がある（追加開発規約の精神）ため棄却。
