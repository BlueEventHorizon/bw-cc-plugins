# Hoge レビュー往復 起床設計（抜粋）

## 背景

Hoge メッセージ基盤の新着検知は pull 型である。停止フックは相手自身のターンが終わったときにしか発火しない。
往復のために常駐させた Bar セッションは、人間が操作しない限りターンを終えず、依頼が滞留する。

過去の運用では、待機が約 7 時間に達した事例、2 ラウンド目以降の恒常的な停止、1 レビューで 4 回の手動起床を要した事例が記録されている。

## 起床の入口

依頼を送った直後に、相手を起こす push 型起床を試みる。

| 項目       | 内容                                                              |
| ---------- | ----------------------------------------------------------------- |
| 契約       | best-effort。構造化された結果を返す。失敗が待機の正しさを壊さない |
| 実装       | Piyo 端末多重化ツールの入力注入を呼ぶ単一の実装                   |
| 不可の場合 | `skipped` を返し、従来どおり相手のターン終了を待つ                |

## 注意

Piyo 経路は、端末の入力欄へ文字列を注入する。下書き中の入力を壊さないよう、注入は安全ゲートを通った場合に限る。
