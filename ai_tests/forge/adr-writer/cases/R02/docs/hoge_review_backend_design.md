# Hoge レビューバックエンド 設計（抜粋）

## 起床

Hoge メッセージ基盤の新着検知は pull 型である。停止フックは相手自身のターンが終わったときにしか発火しない。
常駐セッションでは、人間が操作しない限りターンが終了せず、依頼が滞留する。

このため、依頼を送った直後に相手を起こす push 型起床を持つ。

| 項目         | 内容                                        |
| ------------ | ------------------------------------------- |
| 手段         | Piyo 多重化ツールによる端末入力欄への注入   |
| 失敗時       | `skipped` を返し、待機の正しさは壊さない    |
| 導入されない | 起床は `skipped` となり、往復は人手で進める |

## 監査

往復の履歴は Hoge メッセージ基盤の DB に記録される。レビューの監査はこの履歴で行う。
