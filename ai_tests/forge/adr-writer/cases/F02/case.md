# F02 Bar の API 認証にセッション Cookie を使い、署名付きトークンへ移行しない

- 決定: Bar の管理画面向け API は、サーバー側セッション（セッション ID を Cookie に載せ、状態をサーバーのストアに持つ方式）で認証し、自己完結型の署名付きトークンを使う方式には移行しない。
- 文脈: Bar の管理画面は社内の単一ドメインでのみ使われ、利用者は約 300 人。セキュリティ部門の要請で、退職・権限剥奪の時点から 10 秒以内に既存の操作を止める必要がある。
- 代替案: 署名付きトークンは、サーバーが状態を持たずに水平拡張しやすく、優れて見える。しかしトークンは有効期限まで失効できず、10 秒以内の失効を満たすには失効リストを毎リクエスト参照することになり、状態を持たない利点が消える。有効期限を 10 秒にすると、更新通信が全利用者で毎秒数十件発生し、社内ゲートウェイの上限（毎秒 50 件）に当たる。この判断は、10 秒以内の失効という要請と、ゲートウェイの上限が変わらないことを前提とする。
