# hoge-check ルート判定（抜粋）

## 判定軸

やるべきことを、「対象・変更内容・完了の確認方法」が埋まる TASK として列挙できるかどうかで判定する。変更量・修正規模は判定に使わない。

## ルート

| ルート           | 条件                                                                                                       | 次の工程     |
| ---------------- | ---------------------------------------------------------------------------------------------------------- | ------------ |
| ワンショット実装 | やるべきことを TASK として列挙できる                                                                       | `hoge-build` |
| 要件定義から開始 | 列挙できない項目が残る（要件が定まらない・妥当な解が複数あり選択基準が要件に依存する・影響範囲が閉じない） | `piyo-spec`  |

## 影響範囲が不明な場合

- 深掘りを必須とする。
- 深掘りの結果 TASK が増えても、列挙できるならワンショット実装とする。

## 調査

- 仕様書・実装ルール・類似変更・既存コードを調べ、結果を判定の根拠にする。
- 調査は有限の時間で打ち切る。

## 差分開発の扱い

- feature の新設が要るかどうかの判定は、`hoge-check` では行わず、`piyo-spec` 以降の工程に委ねる。
