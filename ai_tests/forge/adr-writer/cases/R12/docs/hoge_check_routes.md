# hoge-check ルート判定（抜粋）

## 判定軸

「変更の検証・追跡に必要な開発文書の種別」で判定する。変更量・修正規模は判定に使わない。

## ルート

| ルート           | 条件                             | 次の工程                         |
| ---------------- | -------------------------------- | -------------------------------- |
| ワンショット実装 | 既存の仕様書で検証・追跡できる   | `hoge-build`                     |
| 仕様駆動         | 新たな要件定義書か設計書が必要   | `piyo-spec` または `piyo-design` |
| 段取りモード提案 | 対話でしか決着しない決め事が残る | 利用者へ段取りモードを提案       |

## 仕様駆動ルートの入口

- 要件定義書が無い、または新たな要件が要る場合は `piyo-spec` へ進む。
- 有効な要件定義書が既にあり、設計書だけが要る場合は `piyo-design` へ進む。

## 調査

- 仕様書・実装ルール・類似変更・既存コードを調べ、結果を判定の根拠にする。
- 調査は有限の時間で打ち切る。

## 差分開発の扱い

- Foo の差分開発規範に基づき、feature の新設が要るかどうかを、`hoge-check` が判定する。
