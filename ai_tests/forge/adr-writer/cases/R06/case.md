# R06 Hoge メッセージ基盤と Hoge レビューの分離維持

- 決定: Hoge メッセージ基盤と Hoge レビューは、実装完了後も文書として merge せず、恒久的に別 feature として維持する。Hoge レビューの要件定義書・設計書からは一時文書を示す frontmatter を外し、「実装完了後に旧仕様へ merge され削除される予定の一時文書」という位置づけを撤回する。Hoge レビューの仕様書は、Hoge メッセージ基盤の CLI（送信・受信箱・通知の各スクリプト）を外部依存として参照する応用仕様として、専用の仕様ディレクトリに恒久的に存置する。Hoge メッセージ基盤側の仕様書は、Hoge レビューが存在する事実に関する記述を一切追加しない（依存の向きは Hoge レビューから Hoge メッセージ基盤への一方向のみとし、逆方向の言及を持たない）。本 feature の実装は仕様統合手順による統合を実施しない。計画書（計画ファイルと戦略書）のみ、実装完了済みの一時文書として通常どおり破棄可能とする（追加開発規約の「計画 → 破棄」原則は計画文書には引き続き適用する）。
- 文脈: Hoge メッセージ基盤は Foo・Bar 間の汎用エージェント間メッセージング基盤（送受信・履歴・フック登録の仕組み）として設計された。Hoge レビューはその上に構築された応用機能であり、停止フックが差し戻すメッセージに「返信ヒント」（実行可能な返信コマンド案内）を付加することで、レビュー対話における受信側 AI の自己完結的な応答を可能にする。Hoge レビューの全実装タスクが完了した時点で、追加開発規約の通常フローに従い仕様統合手順による本体仕様への統合を開始した。しかし、この統合作業の途中で以下の懸念が指摘された。Hoge レビューの仕様を Hoge メッセージ基盤の仕様へ内容レベルで merge すると、Hoge メッセージ基盤自体の設計書が「返信ヒント付きレビュー対話のための仕組み」であるかのように読める記述に変質してしまう。しかし Hoge メッセージ基盤の本来の価値は、レビュー対話に限らない汎用のエージェント間メッセージング基盤である点にある。将来 Hoge メッセージ基盤を独立した配布単位として切り出し、レビュー対話以外の用途（例: 複数エージェント間の任意の非同期タスク連携）にも配布・応用する可能性を考えると、Hoge メッセージ基盤の仕様書がレビュー用途に特化した記述で汚染されることは、その汎用基盤としての再利用性を損なう。
- 代替案: Hoge メッセージ基盤を本決定のタイミングで即座に独立した配布単位にする: 配布単位の分割は配布・カタログ構成に関わる別種の意思決定であり、本決定のスコープ（文書統合方針）を超える。将来必要になった時点で別途設計判断として扱うため棄却。
