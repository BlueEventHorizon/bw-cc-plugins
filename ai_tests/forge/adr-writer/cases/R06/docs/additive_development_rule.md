# 追加開発規約（抜粋）

## 目的

既存 feature に機能を足すとき、差分を一時文書として管理し、完了後に本体仕様へ統合する。

## 流れ

1. 追加分の要件・設計を、一時文書の印を付けた別ファイルとして書く
2. 実装する
3. 全タスクの完了後、仕様統合手順で追加分を本体仕様へ統合する
4. 統合後、追加分の一時文書は削除する

## 例外: 統合しない場合

追加分を本体仕様へ統合すると、本体仕様の記述が追加分の用途に偏り、本体の汎用性を損なうおそれがある場合は、統合せず、追加分を恒久的な別 feature として残してよい。

- 残す場合は、追加分の文書から一時文書の印を外す
- 追加分の仕様は、本体仕様を外部依存として参照する。本体仕様側は、追加分の存在に言及しない
- 統合するか残すかは、設計判断として決める

## 計画文書

計画ファイルと戦略書は、実装完了後に破棄する。統合しない場合も同じである。
